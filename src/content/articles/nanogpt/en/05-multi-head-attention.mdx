## Attend to several sources at once

The previous chapter fixed `n_head = 1` and followed one attention head. In that case, each position's output is a sum of values weighted by a single set of attention weights.

Predicting a continuation, however, needs several kinds of information at once. For example, useful clues for a character-level model include the previous character, the start of the current word, and the start of the line. When a single head gathers information from these positions, it uses one shared set of attention weights for all these kinds of information.

To gather different kinds of information with separate sets of weights, we use **multi-head attention**. It runs several attention-weight computations side by side, each with its own queries, keys, and values. This lets each head choose its sources independently. The results are then combined into one vector.

In nanoGPT, this mechanism is already built into the [`CausalSelfAttention.forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L52-L76) method from the previous chapter. Since the same code also handles `n_head > 1`, this chapter rereads it with attention on the head axis.

## Split the components by head

The first part of `CausalSelfAttention.forward()` is shown below, with the source comments retained.

```python
B, T, C = x.size() # batch size, sequence length, embedding dimensionality (n_embd)

q, k, v  = self.c_attn(x).split(self.n_embd, dim=2)
k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)
q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)
v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)
```

In the comments, `nh` is the number of heads `H`, and `hs` is the number of components per head, `d = C / H`. The `assert config.n_embd % config.n_head == 0` in `CausalSelfAttention.__init__()` ensures that `C` is divisible by `H`.

`view(B, T, H, d)` cuts each position's `C`-component vector into `H` pieces of **`d` consecutive components**. Head `h` uses components `h·d` through `(h+1)·d − 1`. The following `transpose(1, 2)` moves the head axis in front of the position axis, giving shape `[B, H, T, d]`.

`c_attn` is a single `nn.Linear`, and cutting its output components corresponds to cutting its weight rows. In the `[C, C]` query part of the weight, rows `h·d` through `(h+1)·d − 1` form the `[d, C]` transformation that produces head `h`'s queries. Keys and values work the same way, so **each head has its own Q, K, and V linear transformations**.

The diagram below colors a query vector with `C = 128`, as in the model trained in chapter 11, by head. Changing `H` changes the number of components each head handles and the shapes of the intermediate arrays.

<HeadSplit lang="en" />

Increasing `H` reduces the components per head, `d`, but the weights of `c_attn` and `c_proj` keep shapes `[3C, C]` and `[C, C]` regardless of `H`. The number of heads decides how the same weight elements are divided among independent attention computations.

## Compute attention weights for each head

The following computation uses exactly the same code as the previous chapter:

```python
att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))
att = att.masked_fill(self.bias[:,:,:T,:T] == 0, float('-inf'))
att = F.softmax(att, dim=-1)
att = self.attn_dropout(att)
y = att @ v # (B, nh, T, T) x (B, nh, T, hs) -> (B, nh, T, hs)
```

PyTorch's `@` multiplies over the last two axes and treats the preceding axes `[B, H]` as batch axes. It therefore performs **independent attention computations for every sample and every head** together.

```text
q                         [B, H, T, d]
k.transpose(-2, -1)       [B, H, d, T]
att                       [B, H, T, T]
v                         [B, H, T, d]
y = att @ v               [B, H, T, d]
```

For head `h` of sample `b`, write the two-dimensional arrays $Q^{(h)}$, $K^{(h)}$, and $V^{(h)}$ (each $T \times d$). The computation is:

$$
A^{(h)} = \operatorname{softmax}\!\left(\frac{Q^{(h)}{K^{(h)}}^\top}{\sqrt{d}} + M\right),
\qquad
Y^{(h)} = A^{(h)} V^{(h)}
$$

Scaling uses the number of components per head, `d = k.size(-1)`. The previous chapter had one head, so `d = C`; with `H = 4` and `C = 128`, `d = 32`, so the scores are multiplied by `1/√32`.

The causal mask $M$, meanwhile, is shared by all heads. It is applied by broadcasting `self.bias`, with shape `[1, 1, T, T]`, across the batch and head axes.

Each head uses its own attention weights `att[b, h]` to form a weighted sum of its assigned `d` value components. Because each head can choose its sources independently, even when computing the output at the same position, head 0 can gather information from the previous character while head 3 gathers from the start of the line, for example.

## Place head outputs side by side and mix them with `c_proj`

The `[B, H, T, d]` results gathered by the heads return to the original shape in two lines:

```python
y = y.transpose(1, 2).contiguous().view(B, T, C) # re-assemble all head outputs side by side
y = self.resid_dropout(self.c_proj(y))
```

`transpose(1, 2)` returns to `[B, T, H, d]`, and `view(B, T, C)` joins the last two axes. The vector `y[b, t, :]` at position `t` in sample `b` lists the outputs of head 0 through head `H − 1` in order:

$$
\boldsymbol{y}_{b,t} = \left[\,\boldsymbol{y}^{(0)}_{b,t};\ \boldsymbol{y}^{(1)}_{b,t};\ \dots;\ \boldsymbol{y}^{(H-1)}_{b,t}\,\right]
$$

At this point each head's result occupies its own components. The following `c_proj` (an `nn.Linear(C, C)`) mixes them into a `C`-component output. Split the columns of its weight $W_O$ (shape `[C, C]`) into blocks of `d` columns per head, written $W_O^{(h)}$. Ignoring the bias:

$$
W_O \boldsymbol{y}_{b,t} = \sum_{h=0}^{H-1} W_O^{(h)} \boldsymbol{y}^{(h)}_{b,t}
$$

**Each head writes into the residual stream through its own column block, and the attention output is the sum of these writes.** The previous chapter noted that, with one head, `c_proj` can be absorbed into the value transformation. With several heads, `c_proj` learns how to combine separately gathered information in the `C`-component space.

The amount of computation is also worth checking. The score computation `q @ kᵀ` takes `T × T × d` multiply-adds per head, or `T × T × C` across all `H` heads. Changing the number of heads leaves both the weight elements and the score multiply-adds unchanged. It changes the number of attention-weight sets and the number of components in each.

### Observations

The values in this diagram are actual computations from the trained model, but the observations rest on this model and this input.

1. **Layer 0 heads look nearby.** All four have a mean attention distance of about 3 characters, and their average weight on the previous position ranges from 0.21 to 0.30.
2. **Layer 1, head 3 looks at the start of the line.** Its mean attention distance is 13.8 characters, much larger than the other heads. At most positions inside the second `Good morrow,`, its largest weight falls on the preceding newline (position 51). At position 55 (`d`), for example, the weight is `0.807`.
3. **Layer 1, heads 0 and 1 look at the start of the word.** Selecting the first four letters of `morrow` (`m`, `o`, `r`, `r`; positions 57–60) shows both heads assigning weights of `0.69`–`0.996` to the preceding space (position 56).

### How does the loss change when a head is zeroed?

To investigate a head's role, we deliberately replace its output `y[:, h]` with `0` before `c_proj`. The resulting change in loss shows its effect on prediction.

Evaluating on 200 validation inputs of 64 characters chosen with a fixed seed gave a loss of `1.9107` before zeroing any outputs. This differs from the `1.8857` reported by `train.py` because the selection and number of evaluation inputs differ.

Using this value as the baseline, we zero each head's output one at a time and compare the loss. The largest increase came from layer 0, head 3 (`+0.240`), and the smallest from layer 3, head 3 (`+0.005`). Use “Show statistics for all heads” in the diagram to see the results for every head.

The loss increase indicates how much the rest of the model depends on that head's output. For example, layer 1, head 3 has a clear pattern of attending to line starts, yet zeroing its output increased the loss by only `+0.007`. Investigating each head's role requires looking at both its effect on loss and where it attends.

## Verify in code

Running the training command in chapter 11 saves the trained model to `out-shakespeare-char/ckpt.pt`. The following code uses that checkpoint and `model.py` at the pinned source commit to compute layer 1's multi-head attention by hand. Run it from the nanoGPT directory.

```python
import math
import pickle
import torch
from torch.nn import functional as F
from model import GPT, GPTConfig

ckpt = torch.load('out-shakespeare-char/ckpt.pt', map_location='cpu')
model = GPT(GPTConfig(**ckpt['model_args']))
model.load_state_dict(ckpt['model'])
model.eval()

with open('data/shakespeare_char/meta.pkl', 'rb') as f:
    stoi = pickle.load(f)['stoi']
text = "GREMIO:\nGood morrow, neighbour Baptista.\n\nBAPTISTA:\nGood morrow,"
idx = torch.tensor([[stoi[c] for c in text]])

block = model.transformer.h[1]
B, T = idx.shape
C, H = model.config.n_embd, model.config.n_head
d = C // H

with torch.no_grad():
    x = model.transformer.wte(idx) + model.transformer.wpe(torch.arange(T))
    x = model.transformer.h[0](x)
    x = block.ln_1(x)

    q, k, v = block.attn.c_attn(x).split(C, dim=2)
    q, k, v = [a.view(B, T, H, d).transpose(1, 2) for a in (q, k, v)]
    mask = torch.ones(T, T, dtype=torch.bool).tril()
    att = (q @ k.transpose(-2, -1)) / math.sqrt(d)
    att = F.softmax(att.masked_fill(~mask, float('-inf')), dim=-1)
    y = att @ v
    out = block.attn.c_proj(y.transpose(1, 2).contiguous().view(B, T, C))

    W = block.attn.c_proj.weight
    by_head = sum(y[:, h] @ W[:, h * d:(h + 1) * d].T for h in range(H))

print(list(q.shape), list(att.shape), list(y.shape), list(out.shape))
print(torch.allclose(out, block.attn(x), atol=1e-6))
print(torch.allclose(out, by_head, atol=1e-6))
print(att[0, :, 61].argmax(dim=-1).tolist())
```

This model uses `bias=False`, so `c_proj` has no bias. After the parameter count, the generation environment printed:

```text
[1, 4, 64, 32] [1, 4, 64, 64] [1, 4, 64, 32] [1, 64, 128]
True
True
[61, 61, 58, 51]
```

The first line gives the shapes of the queries, attention weights, per-head aggregates, and attention output. The second line shows agreement between the manual computation and the source module. The third shows that the sum of the per-head column-block contributions equals the `c_proj` output. The last line lists the position each head weights most at position 61; head 3 attends to the newline at position 51.
