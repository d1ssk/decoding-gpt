## From block outputs to vocabulary scores

After all Transformer blocks, the residual stream is still an array of shape `[B, T, C]`. Each position's vector holds information gathered from the context up to that position, but it is not yet in the form “which token comes next.” This chapter turns these vectors into a score for each vocabulary token and connects those scores to probabilities and generation.

The second half of [`GPT.forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L170-L193) is:

```python
for block in self.transformer.h:
    x = block(x)
x = self.transformer.ln_f(x)

if targets is not None:
    # if we are given some desired targets also calculate the loss
    logits = self.lm_head(x)
    loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1), ignore_index=-1)
else:
    # inference-time mini-optimization: only forward the lm_head on the very last position
    logits = self.lm_head(x[:, [-1], :]) # note: using list [-1] to preserve the time dim
    loss = None
```

After the last block, `ln_f` normalizes each position's vector with the same LayerNorm computation seen in the previous chapter. We call the normalized vector the **hidden state** and write it $\boldsymbol{h}_{b,t}$.

Here, `targets` is an array of shape `[B, T]` containing **the ID of the next token to predict at each position**. It is the target array `Y` returned by `get_batch()` in [chapter 2](../02-context-and-training-examples/).

During training and validation, `model(X, Y)` receives these targets and computes a loss by comparing its predictions with them. During generation, `model(idx)` receives only the input, so `targets` takes its default value of `None` and the `else` branch above computes the logits.

`lm_head` is a linear transformation defined in `GPT.__init__()`:

```python
self.lm_head = nn.Linear(config.n_embd, config.vocab_size, bias=False)
```

It maps the `C`-component hidden state to a vector with `V` components, one per vocabulary token. Its output is called the **logits**.

```text
x                 [B, T, C]
ln_f(x)           [B, T, C]
lm_head(ln_f(x))  [B, T, V]
```

With the `lm_head` weight written $W$ (shape `[V, C]`), the score for token `v` at position `t` of sample `b` is the dot product of the hidden state with row `v` of $W$:

$$
\text{logits}_{b,t,v} = \boldsymbol{h}_{b,t}\cdot W_v
$$

Each row of $W$ is a `C`-component vector for one vocabulary token. The more the hidden state points in the same direction as that vector, the larger the token's score.

## Reuse the embedding weights

`GPT.__init__()` contains this line:

```python
self.transformer.wte.weight = self.lm_head.weight # https://paperswithcode.com/method/weight-tying
```

It makes the token-embedding weight `wte` **the same `Parameter` object** as the `lm_head` weight. Both have shape `[V, C]`. This is called **weight tying**.

The same two-dimensional array serves the input and output sides:

| Where it is used      | Computation                                   | Meaning                                 |
| --------------------- | --------------------------------------------- | --------------------------------------- |
| Input side `wte`      | Take row `v`                                  | Represent token `v` with `C` components |
| Output side `lm_head` | Dot product of each row with the hidden state | Score each token from the hidden state  |

Weight tying keeps a single set of $V \times C$ elements. For the GPT-2 vocabulary (`V = 50,304`, `C = 768`) that is about 38.6 million elements; for this chapter's character-level model (`V = 65`, `C = 128`) it is 8,320. During training, gradients reach this weight from both the input and the output side. Chapter 9 separates and checks those two paths.

## Turn scores into probabilities with softmax

Logits are arbitrary real numbers. Softmax normalizes them into probabilities:

$$
p_{b,t,v} = \frac{\exp(\text{logits}_{b,t,v})}{\sum_{u=0}^{V-1}\exp(\text{logits}_{b,t,u})}
$$

At each position, the `V` probabilities are all positive and sum to 1. Adding the same value to every logit leaves the probabilities unchanged, so only the differences between logits matter.

During training, `forward()` computes cross entropy directly from the logits; the next chapter covers the loss. During generation, `generate()` applies softmax explicitly to obtain probabilities and chooses the next token from them.

## Generation uses only the last position

When `forward()` is called without `targets`, it applies `lm_head` only to the last position, because generation needs only the distribution for the token following the input. Indexing with the list `x[:, [-1], :]` keeps the position axis and returns logits of shape `[B, 1, V]`.

[`GPT.generate()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L305-L330), shown below, uses these logits to generate one token at a time. The argument `idx` is an array of input token IDs with shape `[B, T]`, where `B` is the number of sequences processed together and `T` is the number of tokens.

```python
@torch.no_grad()
def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
    """
    Take a conditioning sequence of indices idx (LongTensor of shape (b,t)) and complete
    the sequence max_new_tokens times, feeding the predictions back into the model each time.
    Most likely you'll want to make sure to be in model.eval() mode of operation for this.
    """
    for _ in range(max_new_tokens):
        # if the sequence context is growing too long we must crop it at block_size
        idx_cond = idx if idx.size(1) <= self.config.block_size else idx[:, -self.config.block_size:]
        # forward the model to get the logits for the index in the sequence
        logits, _ = self(idx_cond)
        # pluck the logits at the final step and scale by desired temperature
        logits = logits[:, -1, :] / temperature
        # optionally crop the logits to only the top k options
        if top_k is not None:
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits[logits < v[:, [-1]]] = -float('Inf')
        # apply softmax to convert logits to (normalized) probabilities
        probs = F.softmax(logits, dim=-1)
        # sample from the distribution
        idx_next = torch.multinomial(probs, num_samples=1)
        # append sampled index to the running sequence and continue
        idx = torch.cat((idx, idx_next), dim=1)

    return idx
```

1. **Choose the context for the prediction.** `idx` holds the original input and all tokens generated so far. When its length exceeds `block_size`, take its last `block_size` tokens and pass them to the model as `idx_cond`. For example, with `block_size = 8`, the model uses the most recent 8 tokens. The position embedding provides `block_size` positions, which limits how many tokens the model can take at once.
2. **Compute scores for the next token and adjust how likely each candidate is to be chosen.** In `self(idx_cond)`, `self` is the GPT model itself. The declaration [`class GPT(nn.Module)`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L118) inherits from PyTorch's `nn.Module`, so calling the model like a function runs `forward()` through the calling machinery of `nn.Module` (see the [PyTorch explanation](https://docs.pytorch.org/docs/stable/generated/torch.nn.Module.html#torch.nn.Module.forward)).

   The logits returned by [`forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L170-L193) for the last position give a score for each candidate for the next token. Divide these scores by `temperature`. For example, dividing by `0.5` doubles the score differences, concentrating probability on higher-scoring candidates. Dividing by `2.0` halves the differences, giving lower-scoring candidates a greater chance.

3. **Narrow down the candidates.** With `top_k = 3`, keep the tokens with the top 3 scores. Setting lower scores to `−∞` gives those tokens probability 0 after softmax. The code uses the third-highest score as the cutoff, so tied candidates also remain. Skip this step when `top_k` is unspecified.
4. **Draw one token according to the probabilities.** Softmax turns the scores into probabilities that sum to 1, and `torch.multinomial()` draws one token. For example, if three candidates have probabilities of `60%`, `30%`, and `10%`, each is selected with that probability. Even with the same input, the continuation can vary with the draw.
5. **Append the chosen token and make the next prediction.** Add the selected `idx_next` to the end of `idx`. On the next iteration, use the most recent context, now including that token, to predict the following token. Repeat for `max_new_tokens` iterations.

Dividing by the **temperature** $\tau$ makes each probability proportional to $\exp(z_v/\tau)$. With $\tau < 1$, differences between large logits are emphasized and the distribution becomes sharper; with $\tau > 1$, it becomes flatter. As $\tau$ approaches 0, only the token with the largest logit is chosen.

The name “temperature” comes from the connection to the [Boltzmann distribution](https://web.stanford.edu/~peastman/statmech/statisticaldescription.html) in physics. A state with energy $E_v$ has probability $p_v = \exp(-E_v/(k_B T))/Z$, where $k_B$ is the Boltzmann constant and the denominator $Z$, called the **partition function**, makes the probabilities sum to 1. Identifying $E_v = -z_v$ and $k_B T = \tau$ gives the same form as softmax, whose denominator $\sum_u \exp(z_u/\tau)$ plays the role of the partition function. Lower temperatures concentrate probability on low-energy, high-scoring candidates; higher temperatures allow a wider range of candidates to be selected.

**Top-k** removes low-probability candidates. Their logits become `−∞`, so their probabilities after softmax are 0. The defaults in [`sample.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/sample.py#L17-L18) are `temperature = 0.8` and `top_k = 200`. The character vocabulary has 65 entries, so with `min(top_k, V)` this setting removes no candidates.

### Read out after intermediate blocks

The table below the chart applies `ln_f` and `lm_head` to the stream not only after the last block but also right after the embedding and after each intermediate block. Reading intermediate values this way is called the **logit lens**. The model is trained to be read this way only at the final stream, so treat the intermediate results as an approximation for inspection.

Aggregating the 64 positions gives the following:

1. **Reading the embedding directly predicts the input character itself.** At all 64 positions, the top candidate equals the input character, with an average probability of `0.953`. With weight tying, token `v`'s embedding and $W_v$ are the same vector, so its dot product with itself is large.
2. **Each block raises the target's probability.** The average target probability is `0.077` for the embedding, `0.207` after block 0, then `0.249`, `0.280`, and `0.308` after the last block.
3. **The top candidate matches the target** at 5 positions for the embedding and at 21, 25, 27, and 24 positions after blocks 0–3. The average target probability keeps rising, but the number of top-candidate matches peaks after block 2.

The blocks gradually move vectors that represent the input character toward vectors that predict the next character.

## Verify in code

Using the checkpoint from chapter 11, check weight tying, last-position-only output, and the effect of temperature. The input is the first 57 validation characters; the last is the space after the second `Good`.

```python
import pickle
import torch
from torch.nn import functional as F
from model import GPT, GPTConfig

ckpt = torch.load('out-shakespeare-char/ckpt.pt', map_location='cpu')
model = GPT(GPTConfig(**ckpt['model_args']))
model.load_state_dict(ckpt['model'])
model.eval()

with open('data/shakespeare_char/meta.pkl', 'rb') as f:
    meta = pickle.load(f)
stoi, itos = meta['stoi'], meta['itos']
text = "GREMIO:\nGood morrow, neighbour Baptista.\n\nBAPTISTA:\nGood morrow,"
idx = torch.tensor([[stoi[c] for c in text[:57]]])

with torch.no_grad():
    logits, _ = model(idx)
    tr = model.transformer
    x = tr.drop(tr.wte(idx) + tr.wpe(torch.arange(idx.size(1))))
    for block in tr.h:
        x = block(x)
    h = tr.ln_f(x)

print(model.lm_head.weight is tr.wte.weight)
print(list(logits.shape))
print(torch.allclose(logits[0, -1], h[0, -1] @ tr.wte.weight.T, atol=1e-5))

for temperature in (1.0, 0.5):
    probs = F.softmax(logits[0, -1] / temperature, dim=-1)
    top = torch.topk(probs, 3)
    print(temperature, [(itos[i], round(p, 3)) for i, p in
                        zip(top.indices.tolist(), top.values.tolist())])
```

After the parameter count, the generation environment printed:

```text

[1, 1, 65]
True
1.0 [('t', 0.154), ('s', 0.089), ('m', 0.081)]
0.5 [('t', 0.366), ('s', 0.121), ('m', 0.101)]
```

The first line shows that `lm_head` and `wte` share one `Parameter`. The second shows that `forward()` without `targets` returns logits only for the last position. The third shows that the logits equal the dot products of the hidden state with each row of `wte.weight`. The last two lines show that lowering the temperature concentrates probability on the top candidates.

## Next chapter

This chapter followed the path from the hidden state produced by the Transformer to the choice of the next token. The final LayerNorm and `lm_head` turn the hidden state into vocabulary scores called logits, and softmax converts those scores into probabilities. We saw that `lm_head` shares its weight with the input embedding: the same weight serves both to represent the input and to read out the output.

During generation, temperature and top-k adjust the logits at the last position, and one token is drawn according to the probabilities produced by softmax.

Training compares this probability distribution with the target token and summarizes how far off it is in one number. The next chapter covers that loss, cross entropy.
