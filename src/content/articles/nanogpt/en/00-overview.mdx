nanoGPT supports training GPT-2-style language models and generating text with them. Its minimal implementation makes the model’s mechanisms easier to understand. At its center are roughly 300 lines in `model.py`, which define the model, and roughly 300 lines in `train.py`, which run training. Data preparation, configuration, generation, and benchmarking code surround those two files.

This small codebase includes GPU execution, mixed precision, distributed training, checkpoints, and loading GPT-2 weights. Start by following **one batch of tokens across files and through multidimensional array transformations** to understand the computation flow and each operation's role.

nanoGPT can be organized into four parts:

1. Data preparation that turns text into a token stream
2. The GPT model that turns tokens into next-token predictions
3. The training loop that turns loss into parameter updates
4. Sampling that turns trained weights into generated text

## What nanoGPT covers

nanoGPT is centered on **next-token prediction** with a decoder-only Transformer. Given a token sequence, the model assigns a score to every possible next token at every position. Repeating that computation and updating the weights over a large text corpus gives us pretraining. Continuing from existing weights with a lower learning rate gives us fine-tuning. Feeding each predicted token back into a trained model gives us generation.

```text
pretraining   : random weights + token data → trained weights
fine-tuning   : pretrained weights + new token data → adapted weights
generation    : trained weights + prompt → one token → append → repeat
```

A conversational system such as ChatGPT combines this core with conversation formats, instruction tuning, preference optimization, tool use, serving, and a chat UI. This series first uses nanoGPT to understand the language-modeling core, then moves to nanochat for conversational model training, evaluation, and inference.

### 1. Turn data into token IDs

The model receives a sequence of token IDs. A `prepare.py` script tokenizes text and converts it into those integers.

The character-level [`data/shakespeare_char/prepare.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/data/shakespeare_char/prepare.py#L19-L61) gathers the characters in the corpus, uses `stoi` to map characters to IDs, and uses `itos` for the reverse direction. Datasets that use the same BPE (Byte Pair Encoding, a method that merges frequently occurring sequences into tokens) as GPT-2 rely on `tiktoken` for that role.

Data preparation produces three main files:

- `train.bin`: the token stream used for parameter updates
- `val.bin`: a separate token stream used to estimate loss
- `meta.pkl`: vocabulary size and encode/decode metadata for character data

The binary files contain one long concatenated token stream. Training constructs context windows by taking slices from that stream.

### 2. Create inputs and targets one token apart

[`get_batch()` in `train.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py#L114-L131) randomly selects $B$ starting positions in the token stream. From each position, it takes `block_size` tokens for input `x`. It shifts the starting position forward by one token and takes the same number of tokens for target `y`.

The following shows one sample with `block_size = 8`. Each character is treated as one token for illustration; the actual `x` and `y` contain integer token IDs.

```text
token stream : G  P  T  は  次  を  予  測  す  る
input x      : G  P  T  は  次  を  予  測
target y     : P  T  は  次  を  予  測  す
```

If batch size is $B$ and the number of input tokens is $T$, both `x` and `y` have shape $B \times T$. Here, $T = \texttt{block\_size}$.

At each position, the model **uses the input up to and including that position to predict the next token**. In this example, the first position predicts `P` from `G`, and the last position predicts `す` from `GPTは次を予測` (the full sentence means “GPT predicts the next token”). A causal mask prevents each position from attending to future tokens.

During training, one forward pass computes predictions at all $B \times T$ positions in parallel and compares them with the corresponding targets in `y` to calculate the loss.

### 3. Let GPT compute logits

`x` enters [`GPT.forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L170-L193). First, token embeddings convert each token ID into a high-dimensional vector, while position embeddings convert token positions into vectors of the same dimension. The two are added together. The result passes through multiple Transformer blocks, where self-attention incorporates information from the current and preceding token positions, and an MLP updates each position’s representation. Finally, a linear layer called the language-model head converts each position’s vector into one score per vocabulary token. These scores, before conversion to probabilities, are called **logits**.

```python
logits, loss = model(X, Y)
```

The logits have shape $B \times T \times V$, where $B$ is batch size, $T$ is sequence length, and $V$ is vocabulary size. `logits[b, t, v]` is the score for token `v` following the sequence through position `t` in batch item `b`.

### 4. Update parameters from the loss

When `targets` are provided, `GPT.forward()` also computes cross entropy between the predicted probability distribution at each position and the correct token. The training loop computes gradients from this scalar loss and updates the parameters with AdamW (an optimization method that adaptively adjusts update sizes based on gradients).

```python
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()
```

The real `train.py` adds gradient accumulation, a `GradScaler` for mixed precision, gradient clipping, a learning-rate schedule, and DDP gradient synchronization around this core. These operations help run larger training jobs efficiently and reliably; later chapters examine them in detail.

### 5. Save checkpoints and generate

At regular intervals, training estimates train and validation loss and saves model parameters, optimizer state, the iteration number, and configuration in a checkpoint. `sample.py` restores a checkpoint and calls `model.generate()`.

Generation predicts a continuation from the tokens available so far. It scales the logits from the final position by temperature, optionally restricts the candidates to the top-k, applies softmax, and samples one next token. That token is appended to the input and the process repeats.

## Inside `model.py`

[`model.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py) defines `LayerNorm`, `CausalSelfAttention`, `MLP`, `Block`, and `GPT`, moving from small modules to the complete model. At runtime they are nested like this:

```text
GPT
├── token embedding (wte)         [V, C]
├── position embedding (wpe)      [T, C]
├── Block × n_layer
│   ├── LayerNorm
│   ├── CausalSelfAttention
│   │   ├── c_attn                C → 3C (Q, K, V)
│   │   └── c_proj                C → C
│   ├── LayerNorm
│   └── MLP                       C → 4C → C
├── final LayerNorm
└── language-model head           C → V
```

Here $C$ is the embedding dimension (`n_embd`), and $H$ is the number of attention heads (`n_head`). Each head has dimension $d_{\text{head}} = C/H$, so $C$ must be divisible by $H$. The central shapes move through the model as follows:

| Stage               | Shape                            | Meaning                                         |
| ------------------- | -------------------------------- | ----------------------------------------------- |
| Token IDs           | $B \times T$                     | Indices into the vocabulary                     |
| Token embeddings    | $B \times T \times C$            | Learned vectors for tokens                      |
| Position embeddings | $T \times C$                     | Learned vectors for positions in the sequence   |
| Query / key / value | $B \times H \times T \times C/H$ | Per-head representations                        |
| Attention weights   | $B \times H \times T \times T$   | Weights from each position to earlier positions |
| Residual stream     | $B \times T \times C$            | Hidden states flowing between blocks            |
| Logits              | $B \times T \times V$            | Scores for next-token candidates                |

### Causal self-attention

The input to [`CausalSelfAttention`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L29-L76) is a multidimensional array of shape $B \times T \times C$, representing each token position with a $C$-dimensional vector. The first Transformer block uses representations formed by adding token and position embeddings; subsequent blocks use the previous block's output. Each block applies LayerNorm to normalize the mean and variance of each token position’s vector before passing the representations to `CausalSelfAttention`.

Attention determines how much information each token position takes from itself and preceding positions, then gathers that information according to the weights. **Multi-head attention runs several such computations in parallel, each called a head**. Each head learns its own criteria for weighting positions and its own representations of the information to gather, allowing different heads to capture different relationships and features from the same input.

Each head maps the input’s $C$-dimensional vector to query, key, and value vectors, each with $d_{\text{head}} = C/H$ dimensions. Queries and keys determine the attention weights between positions; values represent the information gathered according to those weights. The implementation combines the linear transformations for all $H$ heads: it transforms each token’s $C$-dimensional vector into $3C$ dimensions, splits it into three $C$-dimensional parts for queries, keys, and values, then splits each part into $H$ heads. Each resulting array has shape $B \times H \times T \times d_{\text{head}}$.

For one head of one sample, queries, keys, and values are two-dimensional arrays $Q$, $K$, and $V$, each of shape $T \times d_{\text{head}}$. The attention weights $A$ and output $Y$ are computed as follows:

$$
A = \operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_{\text{head}}}} + M\right),
\qquad Y = AV
$$

$M$ is a causal mask. It assigns $-\infty$ to future positions, making their weights zero after softmax. This restricts a prediction at position $t$ to information from positions $0$ through $t$.

When PyTorch supports it, nanoGPT uses the fused `scaled_dot_product_attention` implementation. Otherwise it explicitly computes the mask, softmax, and value product in Python. The computation has the same meaning, although the explicit path makes intermediate multidimensional arrays easier to inspect.

### The MLP and residual stream

Attention mixes information across token positions, while the [`MLP`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L78-L92) transforms each token position’s vector individually. A linear transformation expands the vector from $C$ to $4C$ dimensions, the nonlinear activation function GELU is applied, and another linear transformation returns it to $C$ dimensions. Combining the vector’s components (channels) this way allows it to represent more complex features. The MLP applies the same transformation at every position without mixing information between positions.

[`Block`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L94-L106) processes the representations through attention and then an MLP, applying LayerNorm before each operation and adding each output back to that operation’s input. This mechanism is called a residual connection. It provides a direct path for the original information to bypass each operation, making deep networks easier to train.

Both attention and the MLP output $C$-dimensional vectors, so `x` retains the shape $B \times T \times C$ after each addition. The `x` that is updated through these blocks is called the residual stream. This series follows how its values change across layers while its shape stays the same.

### Returning to logits

After all Transformer blocks, a final LayerNorm is applied to the $C$-dimensional vector (hidden state) at each token position. Then `lm_head` computes a next-token score for each of the $V$ tokens in the vocabulary. These $V$-dimensional scores are called logits; applying softmax converts them into probabilities for each token appearing next.

`lm_head` and the token embedding share the same weights. The table used to retrieve a $C$-dimensional vector for each input token ID is reused at the output to compute scores as dot products between the hidden state and each token’s vector.

During training, logits are computed for all positions, giving an output shape of $B \times T \times V$. During text generation, the logits at the final position are used to select the next token.

## Reading `train.py` by responsibility

[`train.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py) looks long, but it becomes manageable when divided into six sections:

1. **Default configuration** — dataset, model size, optimizer, evaluation cadence, and device.
2. **Runtime setup** — single-process or DDP execution, random seeds, device, dtype, and autocast.
3. **Data loading** — open binary data through `np.memmap` and build `X, Y` in `get_batch()`.
4. **Model setup** — start from scratch, resume a checkpoint, or load pretrained GPT-2, then configure the optimizer.
5. **Evaluation and scheduling** — estimate train/validation loss, compute the learning rate, and decide when to checkpoint.
6. **Training loop** — repeat forward, backward, gradient processing, optimizer steps, and logging.

There are three entry points for model initialization:

| `init_from` | Starting state                             | Use                                  |
| ----------- | ------------------------------------------ | ------------------------------------ |
| `scratch`   | Randomly initialized weights               | Start pretraining from the beginning |
| `resume`    | Model and optimizer from `out_dir/ckpt.pt` | Continue an interrupted run          |
| `gpt2*`     | GPT-2 weights loaded through Hugging Face  | Begin evaluation or fine-tuning      |

These paths start with different weights but eventually join the same `GPT` instance and training loop.

## Where training and generation diverge

Training and generation share the same model from token IDs through hidden states and logits. They differ in how those logits are used.

|                    | Training                                | Generation                               |
| ------------------ | --------------------------------------- | ---------------------------------------- |
| Model input        | Token IDs `X` and targets `Y`           | A prompt and all tokens generated so far |
| Logits needed      | Every one of the $B \times T$ positions | Only the final position                  |
| Use of logits      | Compute cross entropy                   | Apply softmax and select a token         |
| Parameters         | Updated through gradients               | Held fixed                               |
| Unit of repetition | One batch                               | One generated token                      |

`train.py` and `sample.py` call the same `GPT.forward()` for training and generation, respectively.

**Linear and LayerNorm `bias`** controls whether these layers have trainable additive terms. A Linear layer adds a bias to its linear transformation. LayerNorm adds a bias after multiplying normalized values by a trainable scale. With `False`, Linear weights and LayerNorm scales still train. For example, `0.2` sets each element to zero with a 20% probability and scales retained values by $1/(1-0.2)$. nanoGPT applies it to the sum of embeddings, attention weights and outputs, and MLP outputs to reduce dependence on particular features. It is disabled during evaluation and text generation. Dropout itself has no trainable parameters.

## How this series proceeds

The remaining chapters revisit the same end-to-end path in four phases.

### Phase 1 — Build the data

Chapters 1–2 turn text into token IDs and build context windows and targets from a long token stream. The central values are `stoi` / `itos`, the token stream, `X [B,T]`, and `Y [B,T]`.

### Phase 2 — Decompose the forward pass

Chapters 3–8 split `GPT.forward()` into embeddings, positions, self-attention, multi-head attention, the MLP, the residual stream, logits, and loss. At each stage we will visualize multidimensional array shapes, value ranges, and the meaning of each axis.

### Phase 3 — Watch the model learn

Chapters 9–11 follow gradients from the loss, inspect how the optimizer updates parameters, and interpret train and validation loss. The phase ends by training a small-scale GPT and comparing its output before and after training.

### Phase 4 — Move to scale and a wider system

Chapter 12 experiments with tradeoffs among parameter count, context length, batch size, and compute. Chapter 13 starts from the pretraining core learned in nanoGPT and examines the additional data, evaluation, inference, and chat-oriented stages introduced by nanochat.
