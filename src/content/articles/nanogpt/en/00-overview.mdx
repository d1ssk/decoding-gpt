## What nanoGPT covers

nanoGPT is code for training GPT-2-style language models and generating text with them. At its center are roughly 300 lines in `model.py`, which define the model, and roughly 300 lines in `train.py`, which run training; data preparation, configuration, generation, and benchmarking code surround them. This small codebase also covers GPU execution, mixed precision, distributed training, checkpoints, and loading pretrained GPT-2 weights.

nanoGPT is centered on **next-token prediction** with a decoder-only Transformer. The model receives a token sequence and, at every position, assigns a score to each candidate for the next token. Repeating that computation and updating the weights over a large text corpus is pretraining. Continuing from existing weights with a lower learning rate is fine-tuning. Feeding each predicted token back onto the end of the input generates text.

```text
pretraining   : random weights + token data → trained weights
fine-tuning   : pretrained weights + new token data → adapted weights
generation    : trained weights + prompt → one token → append → repeat
```

A conversational system such as ChatGPT combines this model with conversation formats, instruction tuning, preference optimization, tool use, a serving system, and a chat interface. This series first reads the language-modeling core in nanoGPT, then moves to nanochat's conversational model in chapter 13.

### 1. Turn text into token IDs

The model receives a sequence of token IDs. The character-level [`data/shakespeare_char/prepare.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/data/shakespeare_char/prepare.py#L19-L61) collects the characters that appear in the corpus to build the vocabulary, uses `stoi` to map characters to IDs, and uses `itos` for the reverse direction. Datasets that use GPT-2's BPE rely on `tiktoken` for the same role.

Preparation produces `train.bin` for training, `val.bin` for validation, and `meta.pkl`, which stores the character vocabulary. Each `.bin` file contains one long token stream made by concatenating the whole text. [Chapter 1](../01-text-to-tokens/) covers this step.

### 2. Create inputs and targets one token apart

[`get_batch()` in `train.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py#L116-L131) randomly selects `B` starting positions in the token stream and takes `block_size` tokens from each as the input `X`. Shifting each start one token forward and taking the same number of tokens gives the target `Y`.

```text
token stream : G  P  T  は  次  を  予  測  す  る
input X      : G  P  T  は  次  を  予  測
target Y     : P  T  は  次  を  予  測  す
```

Each character is treated as one token for illustration (the Japanese sentence means “GPT predicts the next”); the actual `X` and `Y` contain integer token IDs. Both are two-dimensional arrays of shape `[B, T]`, with `T = block_size`. Each position predicts the next token from the input up to that position. One forward pass can compute predictions at all `B × T` positions together because a causal mask prevents positions from attending to the future. [Chapter 2](../02-context-and-training-examples/) covers this step.

### 3. Let GPT compute logits

```python
logits, loss = model(X, Y)
```

[`GPT.forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L170-L193) turns token IDs into embedding vectors, passes them through a stack of Transformer blocks, and finally computes a score for each vocabulary token: the **logits**. The logits have shape `[B, T, V]`, where `V` is the vocabulary size. `logits[b, t, v]` scores token `v` as the continuation of sample `b` through position `t`.

### 4. Update the weights from the loss

When `targets` are provided, `GPT.forward()` also computes the cross entropy between each position's prediction and the correct token. The training loop computes gradients from this scalar loss and updates the weights with AdamW.

```python
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()
```

The real `train.py` adds gradient accumulation, a `GradScaler` for mixed precision, gradient clipping, a learning-rate schedule, and DDP gradient synchronization around this core. [Chapter 8](../08-loss/) covers the loss, [chapter 9](../09-backpropagation/) the gradients, and [chapter 10](../10-training-loop/) the update procedure.

### 5. Save checkpoints and generate

During training, nanoGPT periodically estimates training and validation loss and saves the weights, optimizer state, iteration number, and configuration in a checkpoint. `sample.py` restores a checkpoint and calls `model.generate()`, which repeatedly selects one next token from the final position's logits and appends it to the input. [Chapter 7](../07-hidden-states-to-probabilities/) covers the generation procedure, and [chapter 11](../11-train-a-tiny-gpt/) runs real training and generation.

## Inside `model.py`

[`model.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py) defines `LayerNorm`, `CausalSelfAttention`, `MLP`, `Block`, and `GPT`, moving from small modules to the complete model. At runtime they are nested like this:

```text
GPT
├── token embedding (wte)         [V, C]
├── position embedding (wpe)      [block_size, C]
├── Block × n_layer
│   ├── LayerNorm (ln_1)
│   ├── CausalSelfAttention
│   │   ├── c_attn                C → 3C (Q, K, V)
│   │   └── c_proj                C → C
│   ├── LayerNorm (ln_2)
│   └── MLP                       C → 4C → C
├── final LayerNorm (ln_f)
└── lm_head                       C → V
```

`C` is the embedding dimension (`n_embd`), `H` is the number of attention heads (`n_head`), and `d = C / H` is the number of components per head. The main arrays change shape through the model as follows:

| Stage                   | Shape          | Meaning                                               | Chapter                                            |
| ----------------------- | -------------- | ----------------------------------------------------- | -------------------------------------------------- |
| Token IDs `idx`         | `[B, T]`       | Indices of vocabulary entries                         | [Chapters 1–2](../01-text-to-tokens/)              |
| Sum of embeddings       | `[B, T, C]`    | Vectors for the token and position at each position   | [Chapter 3](../03-embeddings-and-position/)        |
| Query / key / value     | `[B, H, T, d]` | Per-head vectors for matching and aggregation         | [Chapters 4–5](../04-self-attention/)              |
| Attention weights `att` | `[B, H, T, T]` | Weights from each position to itself and earlier ones | [Chapters 4–5](../04-self-attention/)              |
| Residual stream `x`     | `[B, T, C]`    | Per-position vectors flowing between blocks           | [Chapter 6](../06-mlp-and-residual-stream/)        |
| Logits                  | `[B, T, V]`    | Scores for next-token candidates                      | [Chapter 7](../07-hidden-states-to-probabilities/) |
| Loss `loss`             | `[]`           | Mean cross entropy over all positions                 | [Chapter 8](../08-loss/)                           |

Each block passes LayerNorm-normalized vectors to attention and then to the MLP, adding each output to the residual stream. Attention gathers information across positions; the MLP transforms each position's vector individually. The sum keeps the shape `[B, T, C]`, so stacking blocks never changes the shape. After the final LayerNorm, `lm_head` turns each position's vector into `V` scores. The `lm_head` weights are shared with the input-side token embedding.

Attention has two code paths: one calls `scaled_dot_product_attention`, which bundles the computation into a single function, and one computes the mask, softmax, and value product step by step. This series reads the second path, whose intermediate arrays can be inspected.

## Reading `train.py` by responsibility

[`train.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py) becomes manageable when divided into six sections from top to bottom:

1. **Default configuration**: dataset, model size, optimizer, evaluation cadence, device, and so on.
2. **Runtime setup**: single-process or DDP execution, random seeds, device, data type, and autocast.
3. **Data loading**: open binary data with `np.memmap` and build `X, Y` in `get_batch()`.
4. **Model setup**: start from scratch, resume a checkpoint, or load pretrained GPT-2, then configure the optimizer.
5. **Evaluation and scheduling**: estimate training/validation loss, compute the learning rate, and decide when to save a checkpoint.
6. **Training loop**: repeat forward, backward, gradient processing, optimizer steps, and logging.

There are three entry points for model initialization:

| `init_from` | Starting state                             | Use                                  |
| ----------- | ------------------------------------------ | ------------------------------------ |
| `scratch`   | Randomly initialized weights               | Start pretraining from the beginning |
| `resume`    | Model and optimizer from `out_dir/ckpt.pt` | Continue an interrupted run          |
| `gpt2*`     | GPT-2 weights loaded through Hugging Face  | Evaluate or fine-tune                |

All three paths join the same `GPT` instance and the same training loop.

## Where training and generation diverge

Training and generation use the same model from token IDs to logits. They differ in how the logits are used.

|                    | Training                      | Generation                               |
| ------------------ | ----------------------------- | ---------------------------------------- |
| Model input        | Token IDs `X` and targets `Y` | A prompt and all tokens generated so far |
| Logits used        | All `B × T` positions         | Only the final position                  |
| Use of logits      | Compute cross entropy         | Apply softmax and select the next token  |
| Weights            | Updated through gradients     | Held fixed                               |
| Unit of repetition | One batch                     | One generated token                      |

`train.py` and `sample.py` call the same `GPT.forward()` for training and generation, respectively.

The attention count includes the query, key, and value projections ($3C^2$), the output projection ($C^2$), and their biases when enabled. MLP counts include the expansion and contraction projections ($4C^2$ each) and their biases. LayerNorm counts include the scales and biases of two normalizations per block and the final normalization. The attention weights `att` computed for each input are intermediate values and are excluded from this count.

The BPE configuration's 48 blocks, 25 heads, and 1,600 dimensions are selected by [`GPT.from_pretrained()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L207-L234) through `init_from='gpt2-xl'`. OpenWebText uses 50,304 vocabulary entries: GPT-2's 50,257 rounded up to a multiple of 64 for computational efficiency. **Linear and LayerNorm `bias`** controls whether these layers have trainable additive terms. With `False`, Linear weights and LayerNorm scales still train. The `lm_head` always uses `bias=False`, independently of this setting.

**`dropout`** is the probability of randomly setting each element to zero during training. nanoGPT applies it to the sum of embeddings, attention weights and outputs, and MLP outputs. It is disabled during evaluation and generation. [Chapter 3](../03-embeddings-and-position/) explains it in more detail.

## How this series proceeds

The remaining chapters read the same path in four stages.

### Stage 1: Build the data

Chapters 1–2 turn text into token IDs and build batches of inputs and targets from a long token stream. The central values are `stoi` / `itos`, the token stream, `X [B, T]`, and `Y [B, T]`.

### Stage 2: Decompose the forward pass

Chapters 3–8 split `GPT.forward()` into embeddings, self-attention, multi-head attention, the MLP and residual stream, logits, and loss. Each stage visualizes array shapes, value ranges, and the meaning of each axis.

### Stage 3: Watch the model learn

Chapters 9–11 follow how gradients flow from the loss and how the optimizer updates the weights, then train a small GPT and compare its output before and after training.

### Stage 4: Scale and a wider system

Chapter 12 varies model size, training length, and context length and relates them to the loss. Chapter 13 starts from the pretraining core read in nanoGPT and examines the data, evaluation, inference, and conversational stages that nanochat adds.
