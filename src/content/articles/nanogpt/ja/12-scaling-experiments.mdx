## 何を大きくすると損失が下がるか

第 11 章では、80 万パラメータのモデルを 2,000 回更新し、検証損失は約 1.89 になりました。損失をさらに下げるには、モデルを大きくする、長く学習する、長い文脈を使う、といった方法が考えられます。どれも計算量が増えるので、限られた計算資源をどこに使うかが問題になります。

大規模な言語モデルについては、損失がパラメータ数、学習トークン数、計算量に対してべき乗則に近い形で下がることが報告されています（Kaplan et al. 2020、Hoffmann et al. 2022 の Chinchilla）。nanoGPT の [`scaling_laws.ipynb`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/scaling_laws.ipynb) は Chinchilla の結果の一部を再現するノートブックで、[`transformer_sizing.ipynb`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/transformer_sizing.ipynb) はパラメータ数、FLOPs、メモリ使用量を見積もるノートブックです。

この章では、それらの規模にはほど遠い、CPU で数分以内に終わる学習を 28 回行い、同じ問いを小さな規模で確かめます。

## パラメータ数と計算量の数え方

nanoGPT は、起動時に [`get_num_params()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L150-L160) の値を表示します。既定では位置埋め込みを除いた数です（トークン埋め込みは `lm_head` と共有しているので含めます）。この章でも、この数を $N$ とします。

学習の計算量は、[`estimate_mfu()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L289-L303) と同じ式で見積もります。

```python
N = self.get_num_params()
cfg = self.config
L, H, Q, T = cfg.n_layer, cfg.n_head, cfg.n_embd//cfg.n_head, cfg.block_size
flops_per_token = 6*N + 12*L*H*Q*T
```

1 トークンあたりの $6N$ は、重みとの積和 1 回が forward で 2 FLOPs（乗算と加算）、backward で 4 FLOPs になることに対応します。$12LHQT$ は attention のスコア計算と value の集約の分です。学習全体の計算量は、これに学習で処理したトークン数 $D$ を掛けた値で、$T$ が小さければほぼ $6ND$ です。

## 実験の設定

第 11 章の設定（README の CPU 向けの設定）を基準に、次の 4 種類の条件を変えました。どの学習も、第 11 章で使った `train.py` と同じ手順の再実行スクリプトで、seed 1337 で 1 回ずつ行っています。

| 比べる条件       | 変えた設定                                                                                   | 回数 |
| ---------------- | -------------------------------------------------------------------------------------------- | ---: |
| モデルの大きさ   | `n_embd` は 32・64・128・256、`n_layer` は 1・2・4・8 から選んだ組み合わせ（一部）           |   14 |
| 学習の長さ       | `max_iters` と `lr_decay_iters` を両方とも 250・500・1000・2000・4000・8000 のいずれかに設定 |    6 |
| 文脈の長さ       | `block_size` は 8・16・32・64・128・256、`batch_size` = 768 / `block_size`                   |    6 |
| 過学習と dropout | `n_layer` = 6、`n_embd` = 256、6,000 回、`dropout` は 0 または 0.2                           |    2 |

head の成分数は 32 に固定し、`n_head = n_embd / 32` としました。学習率などのほかの設定は、すべて第 11 章と同じです。

学習の後、各モデルの最終的な損失を、学習用・検証用のデータから固定 seed で選んだ 200 本（各 `block_size` 文字）で計算しました。`estimate_loss()` の 20 バッチより安定した値ですが、選び方が異なると 0.02〜0.03 程度の差が出ます。第 11 章のモデルでも、この評価では `1.910`、`train.py` の表示では `1.886` でした。**0.03 より小さい差は、評価の誤差の範囲**として読みます。

### モデルの大きさ：幅が効く

2,000 回の更新で比べると、検証損失は主に `n_embd`（幅）で決まりました。

| `n_embd` | `n_layer` |            $N$ |   検証損失 |
| -------: | --------: | -------------: | ---------: |
|       32 |      1〜4 | 1.4 万〜5.2 万 | 2.43〜2.28 |
|       64 |      1〜8 |  5.4 万〜40 万 | 2.15〜2.07 |
|      128 |      1〜8 |  21 万〜158 万 | 1.93〜1.90 |
|      256 |      2〜8 | 159 万〜631 万 | 1.75〜1.77 |

同じ幅で層を増やした効果は、`n_embd = 32` の 0.15 を除くと 0.08 以下でした。特に、パラメータ数がほぼ同じ 2 つのモデルを比べると、差がはっきりします。

- `n_layer = 8`、`n_embd = 128`（158 万パラメータ）：検証損失 `1.905`
- `n_layer = 2`、`n_embd = 256`（159 万パラメータ）：検証損失 `1.748`

`n_embd = 256` では、層を 2 → 4 → 8 と増やしても検証損失は `1.748`、`1.768`、`1.775` と、評価の誤差の範囲で変わらず、学習時間は 39 秒から 214 秒に増えました。

この結果は、この条件に限った観察です。学習率や更新回数は第 11 章の小さなモデルに合わせたままで、大きなモデルほど 2,000 回では学習が足りていない可能性があります。Chinchilla などの研究は、モデルの大きさに合わせて学習トークン数を増やすことを前提にしています。

一方で、学習用と検証用の損失の差は、モデルが大きいほど広がりました。`n_embd = 32`・`n_layer = 4` では `0.027`、第 11 章のモデルでは `0.158`、`n_embd = 256`・`n_layer = 2` では `0.208` です。約 100 万文字のデータに対して、大きなモデルは学習データ固有のパターンも覚えやすくなります。

### 学習の長さ：更新回数を 2 倍にするたびに下がる

第 11 章のモデルの大きさのまま、更新回数を変えました。学習率のスケジュールは、それぞれの `max_iters` で下がりきるように設定しています。

| `max_iters` | 処理したトークン数 | 学習データを何周したか | 学習用 | 検証用 |    差 |
| ----------: | -----------------: | ---------------------: | -----: | -----: | ----: |
|         250 |              19 万 |                    0.2 |  2.400 |  2.422 | 0.022 |
|         500 |              38 万 |                    0.4 |  2.270 |  2.308 | 0.038 |
|       1,000 |              77 万 |                    0.8 |  2.050 |  2.130 | 0.080 |
|       2,000 |             154 万 |                    1.5 |  1.752 |  1.910 | 0.158 |
|       4,000 |             307 万 |                    3.1 |  1.538 |  1.732 | 0.194 |
|       8,000 |             614 万 |                    6.1 |  1.399 |  1.615 | 0.216 |

更新回数を 2 倍にするたびに、検証損失は 0.11〜0.22 ずつ下がりました。更新回数を 2,000 回から 8,000 回へ 4 倍にすると、検証損失は `1.910` から `1.615` まで下がりました。8,000 回まで学習した実験の総計算量は、推定 3.2 × 10¹³ FLOPs です。一方、モデルを約 8 倍（`n_embd = 256`、`n_layer = 8`）にして 2,000 回学習した場合は、その約 2 倍の 6.1 × 10¹³ FLOPs を使っても `1.775` でした。この規模の実験では、モデルを大きくするより、同じモデルを長く学習するほうが計算量あたりの効果が大きくなりました。

ただし、学習データを何周もすると、学習用と検証用の差が広がります。8,000 回の学習では、`estimate_loss()` による検証損失が 7,000 回目の `1.577` から 8,000 回目の `1.625` に上がり、過学習が始まりつつある様子が見えました。

### 文脈の長さ：バッチの本数との兼ね合い

1 回の更新のトークン数を 768 に固定し、`block_size`（$T$）とバッチサイズ（$768/T$）を変えました。図の線は、入力列の位置 $t$ ごとの検証損失を、位置 0、1、2–3、4–7、… の区間で平均したものです。位置 $t$ の予測には $t + 1$ 文字の文脈しか使えないので、どのモデルでも位置 0 の損失が最も大きく（2.47〜2.75）、文脈が増えるにつれて下がります。

列全体の平均の検証損失は、$T = 32$ の `1.864` が最小で、$T = 8$ では `2.006`、$T = 256$ では `2.186` でした。位置 7 のような先頭近くでも、$T = 128$ と $T = 256$ のモデルの損失（`2.05`、`2.08`）は、$T = 16$ と $T = 32$ のモデル（`1.85`、`1.81`）より大きくなっています。

この実験では、$T$ を大きくすると 1 回の更新に含まれる独立な文章の数が減ります（$T = 256$ では 3 本）。長い文脈を使う能力を身につける前に、少ない本数による勾配のばらつきの影響を受けた可能性があり、2 つの効果を分けることはできません。参照元の `train_shakespeare_char.py` は、`block_size = 256` に `batch_size = 64` を組み合わせ、1 回の更新で 16,384 トークンを使います。長い文脈の効果を確かめるには、バッチの本数を保ったまま学習量を増やす必要があります。

### 過学習と dropout

`n_layer = 6`、`n_embd = 256`（473 万パラメータ）のモデルを 6,000 回（約 4.6 周）学習し、`dropout` 0 と 0.2 を比べました。`estimate_loss()` は `eval_iters = 100` で、ほかの実験より多くのバッチで見積もっています。

- `dropout = 0`：6,000 回目の検証損失は `1.550` で、最後まで下がり続けました。学習用との差は 1,000 回目の `0.122` から 6,000 回目の `0.208` に広がりました。
- `dropout = 0.2`：学習用・検証用ともに損失の下がり方が遅く、6,000 回目の検証損失は `1.647` でした。差は 6,000 回目で `0.200` です。

この範囲では、dropout は学習用と検証用の差をほとんど縮めず、検証損失はかえって高くなりました。dropout は学習を遅くする代わりに過学習を抑える仕組みなので、検証損失が上昇に転じるほど長く学習しないと、効果が現れにくいと考えられます。参照元の設定ファイルが `dropout = 0.2` を使うのは、より大きなモデルを 5,000 回学習する設定です。

以上は Tiny Shakespeare を使った小規模な実験で、各条件を 1 回ずつ学習した結果です。学習率などは第 11 章の設定に固定しており、seed によるばらつきは未検証です。評価にも 0.02〜0.03 程度の誤差があるため、この条件での傾向として読み取ります。

## コードで確かめる

パラメータ数と計算量の見積もりは、学習せずに計算できます。nanoGPT のディレクトリで実行してください。

```python
from model import GPT, GPTConfig

for n_layer, n_embd in [(4, 128), (2, 256), (8, 256)]:
    n_head = n_embd // 32
    model = GPT(GPTConfig(n_layer=n_layer, n_head=n_head, n_embd=n_embd,
                          block_size=64, vocab_size=65, bias=False, dropout=0.0))
    N = model.get_num_params()
    # The per-token count used inside GPT.estimate_mfu()
    L, H, Q, T = n_layer, n_head, n_embd // n_head, 64
    flops_per_token = 6 * N + 12 * L * H * Q * T
    tokens = 12 * 64 * 2001
    print(n_layer, n_embd, N, flops_per_token, f"{flops_per_token * tokens:.2e}")
```

生成環境では、各モデルのパラメータ数の表示に続いて、次の値が得られました。

```text
4 128 795904 5168640 7.94e+12
2 256 1590784 9937920 1.53e+13
8 256 6312448 39447552 6.06e+13
```

各行は、層の数、埋め込みの次元、$N$、1 トークンあたりの FLOPs、2,001 回の更新全体の FLOPs です。実際に学習するには、第 11 章のコマンドで `--n_layer`、`--n_head`、`--n_embd`、`--max_iters`、`--lr_decay_iters` などを変えます。

```bash
python train.py config/train_shakespeare_char.py --device=cpu --compile=False \
  --eval_iters=20 --log_interval=1 --block_size=64 --batch_size=12 \
  --n_layer=2 --n_head=8 --n_embd=256 --max_iters=2000 --lr_decay_iters=2000 \
  --dropout=0.0
```

## 次の章へ

限られた計算量で損失を下げるには、モデルの大きさと学習量の配分が重要です。今回の実験では、モデルを大きくするより、同じモデルを長く学習するほうが効率的でした。
