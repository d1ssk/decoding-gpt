## nanoGPT が扱った範囲

このシリーズでは、nanoGPT で、テキストを token ID にし、GPT で次のトークンの確率を計算し、cross entropy を AdamW で小さくする事前学習（pretraining）の核を読んできました。学習したモデルは、与えられた文章の続きを生成できます。

ChatGPT のように質問に答えるモデルを作るには、この核に加えて、大規模なデータとトークナイザ、評価、会話形式での追加学習、効率のよい推論が必要です。nanoGPT と同じ作者による [nanochat](https://github.com/karpathy/nanochat/tree/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd) は、それらを 1 つのリポジトリにまとめた実装です。この章では、コミット `92d63d4`（2026 年 7 月 3 日）の nanochat を nanoGPT と比べ、何が同じで何が変わるかを確かめます。

## パイプライン全体

nanochat の [`runs/speedrun.sh`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/runs/speedrun.sh) は、8 GPU の計算機で、GPT-2 と同程度の性能のモデルを学習し、対話できるようにするまでの手順をまとめたスクリプトです。環境構築を除く主な手順を抜粋し、説明用コメントを付けています。

## モデル構造の共通点と変更点

[`nanochat/gpt.py`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L1-L13) の冒頭には、nanoGPT からの主な変更点が列挙されています。

```python
"""
GPT model (rewrite, a lot simpler)
Notable features:
- rotary embeddings (and no positional embeddings)
- QK norm
- untied weights for token embedding and lm_head
- relu^2 activation in MLP
- norm after token embedding
- no learnable params in rmsnorm
- no bias in linear layers
- Group-Query Attention (GQA) support for more efficient inference
- Flash Attention 3 integration
"""
```

[`Block.forward()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L144-L153) の基本構造は nanoGPT と同じです。正規化した入力を attention と MLP に渡し、その出力を残差ストリームに足します（第 6 章）。

```python
def forward(self, x, ve, cos_sin, window_size, kv_cache):
    x = x + self.attn(norm(x), ve, cos_sin, window_size, kv_cache)
    x = x + self.mlp(norm(x))
    return x
```

以下、主な変更点を順に見ていきます。

### 位置の表し方：RoPE

nanoGPT は、位置ごとに学習するベクトル `wpe` を埋め込みに足していました（第 3 章）。nanochat には位置埋め込みがありません。代わりに、attention の中で query と key を**位置に応じた角度だけ回転**させます。この方式を RoPE（rotary position embedding）と呼びます。[`CausalSelfAttention.forward()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L99-L104) の該当部分は次のとおりです。

```python
cos, sin = cos_sin
q, k = apply_rotary_emb(q, cos, sin), apply_rotary_emb(k, cos, sin)
q, k = norm(q), norm(k) # QK norm
q = q * 1.2  # sharper attention (split scale between Q and K), TODO think through better
k = k * 1.2
```

[`apply_rotary_emb()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L57-L65) は、head の `d` 成分を前半と後半に分け、成分 `i` と `i + d/2` を 1 組の 2 次元ベクトルとして回転させます。

```python
def apply_rotary_emb(x, cos, sin):
    # note: this rotates by -theta, the transpose of the textbook convention. Functionally
    # equivalent (only the relative q/k rotation matters), kept for checkpoint compatibility.
    assert x.ndim == 4  # multihead attention
    d = x.shape[3] // 2
    x1, x2 = x[..., :d], x[..., d:] # split up last dim into two halves
    y1 = x1 * cos + x2 * sin # rotate pairs of dims
    y2 = x1 * (-sin) + x2 * cos
    return torch.cat([y1, y2], 3)
```

位置 $m$ の組 $i$ を回転させる角度は $m\,\omega_i$ で、周波数は [`_precompute_rotary_embeddings()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L270-L285) で $\omega_i = 100000^{-2i/d}$ と決まります。組ごとに回転の速さが異なり、$i = 0$ は 1 位置あたり 1 ラジアン、$i$ が大きいほどゆっくり回ります。

回転後の内積は、回転前の query・key の値と、相対位置 $m - n$ によって決まります。重要なのは、**同じ query・key なら、両方の位置を同じだけずらしても内積が変わらない**ことです。各組で query を $-m\omega_i$、key を $-n\omega_i$ だけ回転させるため、位置を同じだけずらすと、両方に同じ角度の回転が加わります。すると、ベクトルの長さと互いの角度が保たれ、内積も変わりません。

これにより、「直前のトークンを参照する」といった規則を、文章中の位置が変わっても利用しやすくなります。どの内容と距離を重視するかは、query と key を作る重みの学習で決まります。

次の図は、回転前の query と key を固定し、nanochat の関数そのもので計算した説明用の例です。`m` と `n` を動かすと、組 0 と組 1 の平面で、位置による回転と内積の変化を確かめられます。下の表は、すべての $(m, n)$ の組み合わせの内積です。

<RotaryPositions lang="ja" />

表では、左上から右下へ向かう対角線（相対位置 $m - n$ が等しい組）に同じ色が並びます。生成スクリプトでは、16 × 16 のすべての組み合わせで $s_{m,n} = s_{m+1,n+1}$ が成り立つことを確認しています。

位置埋め込みの表がないので、nanoGPT の `block_size` のような「学習した位置の数」による上限もありません。nanochat は `sequence_len` の 10 倍の長さまで `cos` と `sin` をあらかじめ計算しておきます。

### 正規化：RMSNorm と QK norm

nanoGPT の LayerNorm は、平均を引き、標準偏差で割り、学習する `weight` を掛けました（第 6 章）。nanochat の [`norm()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L42-L43) は、学習するパラメータを持たない RMSNorm です。

```python
def norm(x):
    return F.rms_norm(x, (x.size(-1),)) # note that this will run in bf16, seems ok
```

$$
\operatorname{RMSNorm}(\boldsymbol{x})_c = \frac{x_c}{\sqrt{\frac{1}{C}\sum_{c'} x_{c'}^2 + \varepsilon}}
$$

平均を引かずに、2 乗平均の平方根で割ります。nanochat はこの `norm()` を、各サブレイヤーの前と最終層の前に加えて、トークン埋め込みの直後と、回転後の query と key にも適用します。query と key の正規化（QK norm）によって、内積の大きさが重みの大きさに左右されにくくなり、softmax の重みが極端に偏ることを抑えます。

### MLP の活性化関数：ReLU²

[`MLP`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L131-L141) の構造（`C → 4C → C`）は nanoGPT と同じで、活性化関数が GELU から ReLU の 2 乗に変わっています。

<ActivationComparison lang="ja" />

```python
def forward(self, x):
    x = self.c_fc(x)
    x = F.relu(x).square()
    x = self.c_proj(x)
    return x
```

ReLU² は負の入力で 0、正の入力で $x^2$ を返します。GELU は負の入力で小さな負の値を取り、正の入力が大きくなると出力が $x$ に近づきます。「0 付近」に切り替えると、負の側の違いを確認できます。

### 埋め込みと出力層

学習前の予測がほぼ一様分布になる点は、第 8 章で見た nanoGPT と共通です。違いは重みの共有と初期化にあります。nanoGPT は `wte` と `lm_head` の重みを共有し、標準偏差 0.02 で初期化します。nanochat は両者を分け、`lm_head` を標準偏差 0.001 で初期化します。

さらに、[`forward()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L510-L515) は logits を $15\tanh(z/15)$ で $\pm 15$ の範囲に滑らかに制限します。

```python
softcap = 15 # smoothly cap the logits to the range [-softcap, softcap]
logits = self.lm_head(x) # (B, T, padded_vocab_size) <- very big tensor, large amount of memory
logits = logits[..., :self.config.vocab_size] # slice to remove padding
logits = logits.float() # switch to fp32 for logit softcap and loss computation
logits = softcap * torch.tanh(logits / softcap) # squash the logits
```

損失の計算は nanoGPT と同じ `F.cross_entropy(..., ignore_index=-1)` です。

### 同じ大きさのモデルでパラメータを比べる

第 11 章のモデルと同じ大きさ（`n_layer = 4`、`n_head = 4`、`n_embd = 128`、語彙 65、文脈 64）で、両方の実装のモデルを作り、パラメータ数を数えました。

| 内訳                    |          nanoGPT |    nanochat |
| ----------------------- | ---------------: | ----------: |
| トークン埋め込み `wte`  |            8,320 |      16,384 |
| 位置埋め込み `wpe`      |            8,192 |           — |
| 出力層 `lm_head`        | （`wte` と共有） |      16,384 |
| value embedding         |                — |      32,768 |
| block 内の 2 次元の重み |          786,432 |     786,528 |
| LayerNorm の `weight`   |            1,152 |           — |
| 層ごとのスカラーなど    |                — |          34 |
| **合計**                |      **804,096** | **852,098** |

nanochat は語彙サイズを 64 の倍数に切り上げるので、65 は 128 になり、`wte` と `lm_head` はそれぞれ 128 × 128 です。value embedding は、一部の層で value にトークンごとのベクトルを加える、nanochat 独自の仕組みです。block 内の重みの差 96 は、その強さを決めるゲートです。学習前の nanochat のモデルでランダムな token ID の損失を計算すると `4.1738` で、一様分布の $\ln 65 = 4.1744$ とほぼ一致しました。

### attention の効率化と追加の工夫

- **Group-Query Attention**：`n_kv_head` を `n_head` より小さくすると、複数の query の head が key と value の head を共有します。推論時に保存する key と value が減ります。
- **sliding window attention**：`window_pattern = "SSSL"` のように、一部の層は直近の範囲（文脈長の約 4 分の 1）だけを参照します。最後の層は常に全範囲を参照します。
- **Flash Attention 3**：対応する GPU では専用の実装を使い、それ以外では PyTorch の `scaled_dot_product_attention` を使います（第 4 章の補足と同じ関数）。
- そのほか、層ごとに残差ストリームの倍率を学習する `resid_lambdas`、埋め込みを各層に混ぜ直す `x0_lambdas` など、学習時間を短縮するために調整された仕組みが加わっています。

## 学習：データ、トークナイザ、optimizer、規模

### トークナイザを学習する

nanoGPT は、文字単位の語彙か、GPT-2 の BPE をそのまま使いました（第 1 章）。nanochat は、学習データから BPE のトークナイザを自分で学習します。既定の語彙サイズは $2^{15} = 32{,}768$ です。語彙には、会話を表すための[特殊トークン](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/tokenizer.py#L9-L21)も含まれます。

```python
SPECIAL_TOKENS = [
    # every document begins with the Beginning of Sequence (BOS) token that delimits documents
    "<|bos|>",
    # tokens below are only used during finetuning to render Conversations into token ids
    "<|user_start|>", # user messages
    "<|user_end|>",
    "<|assistant_start|>", # assistant messages
    "<|assistant_end|>",
    "<|python_start|>", # assistant invokes python REPL tool
    "<|python_end|>",
    "<|output_start|>", # python REPL outputs back to assistant
    "<|output_end|>",
]
```

### optimizer：Muon と AdamW

nanoGPT はすべての重みを AdamW で更新しました（第 10 章）。nanochat の [`setup_optimizer()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py#L419-L457) は、パラメータを役割ごとに分け、異なる更新則と学習率を割り当てます。

- **block 内の 2 次元の重み**：Muon。過去の勾配を反映した更新用の 2 次元配列に、方向ごとの強さの偏りを抑える「直交化」の処理を加えます。ここでいう直交化は、行（縦長の配列なら列）のベクトルを、互いに直角で長さが 1 の状態にそろえることです。実装では、少数回の反復計算でこの状態に近づけます。
- **埋め込み、`lm_head`、スカラー**：AdamW。グループごとに学習率と $\beta$ を変えています。

### 規模を 1 つの値で決める

nanoGPT では `n_layer`、`n_head`、`n_embd` を個別に指定しました。nanochat の [`scripts/base_train.py`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/scripts/base_train.py#L129-L140) は、層の数 `--depth` から残りを決めます。埋め込みの次元は `depth × 64` を head の成分数 128 の倍数に切り上げた値で、head 数はそれを 128 で割った値です。`speedrun.sh` の `--depth=24` では、次元 1,536、head 数 12 になります。学習するトークン数も、パラメータ数に比例するように決めます。

### 評価

nanochat は、検証損失を **bits per byte**（bpb）で表します。トークンごとの損失の合計を、正解のトークンが表すバイト数の合計で割った値で、語彙の異なるトークナイザの間でも比較できます。さらに、多肢選択や文章の続きを使う複数のベンチマークをまとめた CORE スコアや、会話モデル向けの課題（ARC、GSM8K、HumanEval、MMLU など）で評価します。

## 対話モデルへ

### 会話をトークン列にして、応答だけを学習する

SFT は **Supervised Fine-Tuning（教師あり追加学習）** の略です。ここでは、事前学習済みのモデルに、質問と望ましい応答の例を使って返答の仕方を学ばせます。

まず、会話を [`render_conversation()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/tokenizer.py#L140-L224) で 1 本のトークン列に変換します。同時に、各トークンを学習の対象にするかどうかの mask を作ります。次の表は、ユーザーの質問 1 つとアシスタントの応答 1 つからなる会話の概念図です（実際のトークン分割は省略しています）。

| 部分                    | 例                        | mask |
| ----------------------- | ------------------------- | ---: |
| `<\|bos\|>`             |                           |    0 |
| `<\|user_start\|>`      |                           |    0 |
| ユーザーの発話          | `Why is the sky blue?`    |    0 |
| `<\|user_end\|>`        |                           |    0 |
| `<\|assistant_start\|>` |                           |    0 |
| アシスタントの発話      | `Because of Rayleigh ...` |    1 |
| `<\|assistant_end\|>`   |                           |    1 |

mask が 1 なのは、アシスタントが生成すべき部分だけです。[`scripts/chat_sft.py`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/scripts/chat_sft.py#L284-L289) は、mask が 0 の位置の正解を `-1` にします。

```python
# Apply the loss mask from render_conversation (mask=1 for assistant completions,
# mask=0 for user prompts, BOS, special tokens, tool outputs). mask[1:] aligns
# with targets (shifted by 1). Unmasked positions get -1 (ignore_index).
mask_tensor = torch.tensor(mask_rows, dtype=torch.int8)
mask_targets = mask_tensor[:, 1:].to(device=device)
targets[mask_targets == 0] = -1
```

第 8 章で見た `ignore_index=-1` によって、ユーザーの発話などは損失の平均から除かれます。モデルは会話全体を入力として読みながら、アシスタントの応答だけを予測するように学習します。入力と正解を 1 トークンずらす点（`mask[1:]`）は、第 2 章の `X` と `Y` と同じです。

### KV cache で 1 トークンずつ生成する

nanoGPT の `generate()` は、1 トークン生成するたびに、それまでの入力全体を `forward()` に通していました（第 7 章）。過去の位置の key と value は毎回同じなので、この計算は重複しています。

nanochat の [`Engine.generate()`](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/engine.py#L176-L276) は、各層の key と value を **KV cache** に保存します。最初にプロンプト全体を 1 回通して cache を作り（prefill）、その後は新しい 1 トークンだけを入力して、cache の key と value と合わせて attention を計算します。

```python
ids = torch.tensor(token_column, dtype=torch.long, device=device).unsqueeze(1)
logits = self.model.forward(ids, kv_cache=kv_cache_decode)[:, -1, :]  # (B, vocab_size)
```

1 トークンだけを入力するときも、RoPE には文章全体での位置を使います。例えば、cache に 5 トークン分（位置 0〜4）の key と value が保存されていれば、次のトークンの位置は 5 です。`kv_cache.get_pos()` はこの保存済みのトークン数を返し、その位置に対応する角度で新しい query と key を回転させます。これにより、保存済みの key との内積にも正しい相対位置が反映されます。

### 計算機能を呼び出す（tool use）

**tool use** は、モデルが生成の途中で外部の機能を呼び出し、その結果を使って続きを生成する仕組みです。`Engine.generate()` の計算機能なら、例えば次のように進みます。

1. モデルが `<|python_start|>2 + 3<|python_end|>` を生成し、計算を依頼します。
2. `Engine.generate()` が式を計算し、`<|output_start|>5<|output_end|>` をトークン列に挿入します。
3. モデルがその結果を読み、「答えは 5 です」といった続きを生成します。

SFT では、計算式と結果を使った返答を学習します。計算機能が返す部分（上の 2）は、区切りのトークンも含めて mask を 0 にし、予測の誤差を損失に含めません。この部分も入力としては読み込むので、結果を踏まえた返答を学べます。

## nanoGPT シリーズのまとめ

このシリーズで読んだ内容は、nanochat でもそのまま土台になっています。

- テキストを token ID の列にし、1 トークンずらした入力と正解で次のトークンを予測する（第 1・2 章）。
- 埋め込み、self-attention、multi-head attention、MLP、残差ストリームで各位置のベクトルを更新する（第 3〜6 章）。
- 語彙のスコアから確率と cross entropy を計算し、誤差逆伝播で勾配を求め、optimizer で更新する（第 7〜10 章）。
- 損失の推移と生成結果、規模を変えた実験で、学習を評価する（第 11・12 章）。

nanochat では、位置の表し方、正規化、活性化関数、optimizer などの構成要素が変わり、トークナイザの学習、会話形式の追加学習、評価、KV cache を使う推論が加わります。次の nanochat シリーズでは、これらを順に読んでいく予定です。
