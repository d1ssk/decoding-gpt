## Transformer block の 2 行

前章までで、attention がほかの位置から情報を集める仕組みを見てきました。Transformer block にはさらに **MLP** という操作もあります。その両者をつなぐのが、 [`Block.forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L94-L106) の 2 行です。

```python
class Block(nn.Module):

    def __init__(self, config):
        super().__init__()
        self.ln_1 = LayerNorm(config.n_embd, bias=config.bias)
        self.attn = CausalSelfAttention(config)
        self.ln_2 = LayerNorm(config.n_embd, bias=config.bias)
        self.mlp = MLP(config)

    def forward(self, x):
        x = x + self.attn(self.ln_1(x))
        x = x + self.mlp(self.ln_2(x))
        return x
```

2 行とも同じ形をしています。

1. `x` を LayerNorm で正規化する。
2. 正規化したベクトルを attention または MLP に渡す。
3. その出力を、正規化する前の `x` に足す。

attention と MLP を、ここでは**サブレイヤー**と呼びます。どちらのサブレイヤーも形状 `[B, T, C]` の配列を受け取り、同じ形状の配列を返します。足し算の結果も `[B, T, C]` なので、block を何層重ねても `x` の形状は変わりません。

この足し算でつながっていく `x` を **残差ストリーム（residual stream）** と呼びます。各サブレイヤーは、LayerNorm を通してストリームを読み、計算結果をストリームに足し込みます。この章では、LayerNorm、MLP、残差ストリームの順に見ていきます。

## LayerNorm：各位置のベクトルの尺度をそろえる

nanoGPT は PyTorch の `nn.LayerNorm` の代わりに、bias を省略できる自前の [`LayerNorm`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L18-L27) を使います。

```python
class LayerNorm(nn.Module):
    """ LayerNorm but with an optional bias. PyTorch doesn't support simply bias=False """

    def __init__(self, ndim, bias):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(ndim))
        self.bias = nn.Parameter(torch.zeros(ndim)) if bias else None

    def forward(self, input):
        return F.layer_norm(input, self.weight.shape, self.weight, self.bias, 1e-5)
```

`F.layer_norm(input, (C,), ...)` は、最後の軸の `C` 成分ごとに、つまり**各サンプル・各位置のベクトルごとに**正規化します。サンプル `b` の位置 `t` にあるベクトルを $\boldsymbol{x}$ とすると、成分 $c$ の出力は次のとおりです。

$$
\mu = \frac{1}{C}\sum_{c=0}^{C-1} x_c,\qquad
\sigma^2 = \frac{1}{C}\sum_{c=0}^{C-1} (x_c-\mu)^2,\qquad
\operatorname{LN}(\boldsymbol{x})_c = \frac{x_c-\mu}{\sqrt{\sigma^2+\varepsilon}}\,\gamma_c + \beta_c
$$

$\varepsilon = 10^{-5}$ は 0 除算を防ぐ小さな固定値です。$\gamma$ は `weight`（初期値 1）、$\beta$ は `bias`（初期値 0）で、どちらも学習します。この章のモデルは `bias=False` なので $\beta$ はありません。

$\gamma$ と $\beta$ を適用する前の正規化した値は、成分の平均が 0 、標準偏差がほぼ 1 になります。その後に成分ごとの $\gamma$ と $\beta$ を適用するので、最終出力の平均と標準偏差は、学習したパラメータにも依存します。

次の図は、第 11 章で学習するモデルで、位置 52 のベクトルが層 0 の `ln_1` に入る様子です。入力の標準偏差は約 `0.073` で、$\gamma$ を掛ける前の正規化によってほぼ 1 になります。スライダーで入力のすべての成分に同じ値を足したり、同じ値を掛けたりしても、この段階の値はほとんど変わりません。

<LayerNormDemo lang="ja" />

LayerNorm は、ベクトルの**向きの情報**（成分どうしの相対的な大小）を残し、全体の位置と大きさを取り除きます。そのうえで、学習した `weight` が成分ごとの尺度を付け直します。

nanoGPT では、すべての block の後に、もう 1 つ LayerNorm（`ln_f`）があります。最後のストリームを正規化してから語彙のスコアを計算する部分は、次章で扱います。

## MLP：各位置のベクトルを個別に変換する

[`MLP`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L78-L92) は、2 つの線形変換の間に活性化関数 GELU を挟んだモジュールです。

```python
class MLP(nn.Module):

    def __init__(self, config):
        super().__init__()
        self.c_fc    = nn.Linear(config.n_embd, 4 * config.n_embd, bias=config.bias)
        self.gelu    = nn.GELU()
        self.c_proj  = nn.Linear(4 * config.n_embd, config.n_embd, bias=config.bias)
        self.dropout = nn.Dropout(config.dropout)

    def forward(self, x):
        x = self.c_fc(x)
        x = self.gelu(x)
        x = self.c_proj(x)
        x = self.dropout(x)
        return x
```

形状は次のように変わります。`4C` 成分の中間の値を、ここでは**中間層**と呼びます。

```text
x              [B, T, C]
c_fc(x)        [B, T, 4C]
gelu(...)      [B, T, 4C]
c_proj(...)    [B, T, C]
```

`nn.Linear` は各位置のベクトルに同じ変換を適用するのでした。GELU も成分ごとの関数なので、**MLP は位置どうしの情報を混ぜません**。attention が位置の間で情報を移し、MLP が各位置で集まった情報を変換する、という役割分担になっています。

### 中間層の 1 成分が行うこと

`c_fc` の重みの行 `i` を $\boldsymbol{w}^{\text{in}}_i$、`c_proj` の重みの列 `i` を $\boldsymbol{w}^{\text{out}}_i$ と書くと、bias を除いて MLP の出力は次のように書けます。

$$
\operatorname{MLP}(\boldsymbol{x}) = \sum_{i=0}^{4C-1} \operatorname{GELU}\!\left(\boldsymbol{w}^{\text{in}}_i\cdot\boldsymbol{x}\right)\,\boldsymbol{w}^{\text{out}}_i
$$

中間層の成分 `i` は、入力と $\boldsymbol{w}^{\text{in}}_i$ の内積で「入力がその方向をどれだけ向いているか」を測ります。GELU を通した値が、固定されたベクトル $\boldsymbol{w}^{\text{out}}_i$ に掛かり、出力に足されます。MLP の出力は、`4C` 本の固定ベクトルを、入力に応じた係数で足し合わせたものです。

### GELU

`nn.GELU()` は、標準正規分布の累積分布関数 $\Phi$ を使った関数です。

$$
\operatorname{GELU}(u) = u\,\Phi(u) = \frac{u}{2}\left(1+\operatorname{erf}\frac{u}{\sqrt{2}}\right)
$$

正の大きな $u$ ではほぼ $u$、負の大きな $u$ ではほぼ 0 になります。0 付近では滑らかに変化し、$u \approx -0.75$ で最小値 $-0.17$ をとります。この非線形性がなければ、2 つの線形変換は 1 つの線形変換にまとまってしまいます。

次の図は、GELU の曲線に、学習済みモデルの中間層の値 `u = c_fc(x)` の分布を重ねたものです。検証データの 200 本 × 64 位置 × 512 成分を集計しています。

<MlpActivations lang="ja" />

どの層でも、`u > 0` となる成分は 21–36% です。残りの成分では GELU の出力がほぼ 0 になり、対応する $\boldsymbol{w}^{\text{out}}_i$ はほとんど出力に寄与しません。各位置では、`4C` 本のベクトルのうち一部だけが使われています。

MLP の重みの要素数は、`c_fc` と `c_proj` を合わせて $8C^2$ です（bias を除く）。attention の $4C^2$ の 2 倍で、モデルの重みの大部分を占めます。

## 残差ストリーム：足し算で情報を積み上げる

`Block.forward()` の足し算をすべての block について展開すると、最後の block の出力 $\boldsymbol{x}_{\text{final}}$ は次の和になります。

$$
\boldsymbol{x}_{\text{final}} = \boldsymbol{x}_{\text{emb}} + \sum_{l=0}^{L-1}\left(\boldsymbol{a}_l + \boldsymbol{m}_l\right)
$$

ここで、$\boldsymbol{a}_l$ と $\boldsymbol{m}_l$ は層 $l$ の attention と MLP の出力、$\boldsymbol{x}_{\text{emb}}$ は第 3 章で作った埋め込みの和です。つまり、各サブレイヤーはストリームの値を書き換えるのではなく、自分の出力を足すだけです。また、各層では、それまでのすべての書き込みの和を LayerNorm 越しに読みます。

この足し算は、学習時の勾配の伝わり方にも関わります。1 回の残差接続を `y = x + f(x)` と書くと、`f` は LayerNorm と、それに続く attention または MLP の計算です。入力 `x` は、`f` で変換する経路と、そのまま足す経路の両方から `y` に影響します。

足し算の微分は恒等写像なので、直接足す経路では、`y` に届いた損失の勾配がそのまま `x` に伝わります。一方、`f` を通る経路では、勾配はその計算に応じて変化しながら `x` に戻ります。

最終的に `x` に届く勾配は、直接戻る分と、`f` の計算に応じて変化して戻る分の和です。直接の経路があることで、サブレイヤーの変換を経由せずに前の層へ学習の信号を伝えられます。具体的な勾配の計算は第 9 章で確かめます。

### 書き込みの大きさを初期化で調整する

[`GPT.__init__()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L140-L145) は、重みを初期化した後、ストリームへ書き込む線形変換だけを特別に小さく初期化します。

```python
# apply special scaled init to the residual projections, per GPT-2 paper
for pn, p in self.named_parameters():
    if pn.endswith('c_proj.weight'):
        torch.nn.init.normal_(p, mean=0.0, std=0.02/math.sqrt(2 * config.n_layer))
```

`c_proj` は attention と MLP の最後の線形変換で、どちらもストリームへの書き込みを作ります。書き込みは $2L$ 回あるので、標準偏差を $1/\sqrt{2L}$ 倍して、初期状態で和が層の数とともに大きくなりすぎないようにしています。

## コードで確かめる

第 11 章で学習したチェックポイントを使い、ストリームが書き込みの和になっていること、LayerNorm と GELU が上の式どおりであることを確かめます。nanoGPT のディレクトリで実行してください。

```python
import math
import pickle
import torch
from model import GPT, GPTConfig

ckpt = torch.load('out-shakespeare-char/ckpt.pt', map_location='cpu')
model = GPT(GPTConfig(**ckpt['model_args']))
model.load_state_dict(ckpt['model'])
model.eval()

with open('data/shakespeare_char/meta.pkl', 'rb') as f:
    stoi = pickle.load(f)['stoi']
text = "GREMIO:\nGood morrow, neighbour Baptista.\n\nBAPTISTA:\nGood morrow,"
idx = torch.tensor([[stoi[c] for c in text]])
tr = model.transformer

with torch.no_grad():
    x = tr.drop(tr.wte(idx) + tr.wpe(torch.arange(idx.size(1))))
    writes = [x]
    for block in tr.h:
        a = block.attn(block.ln_1(x))
        x = x + a
        m = block.mlp(block.ln_2(x))
        x = x + m
        writes += [a, m]

    print(torch.allclose(sum(writes), x, atol=1e-5))
    print([round(w[0, 52].norm().item(), 2) for w in writes])

    ln = tr.h[0].ln_1
    v = writes[0][0, 52]
    manual = (v - v.mean()) / torch.sqrt(v.var(unbiased=False) + 1e-5) * ln.weight
    print(torch.allclose(manual, ln(v), atol=1e-6))

    u = torch.linspace(-3, 3, 7)
    gelu = 0.5 * u * (1 + torch.erf(u / math.sqrt(2)))
    print(torch.allclose(tr.h[0].mlp.gelu(u), gelu, atol=1e-6))
```

パラメータ数の表示に続き、生成環境では次の結果が得られました。

```text
True
[0.83, 0.62, 5.85, 1.8, 2.15, 1.58, 3.53, 2.34, 4.25]
True
True
```

1 行目は、最後の block の出力が埋め込みと 8 個の書き込みの和に一致することを示します。2 行目は、位置 52 での各書き込みのノルムで、上の図の棒と同じ値です。3 行目と 4 行目は、LayerNorm と GELU を式どおりに計算した結果がモジュールの出力と一致することを示します。

## 次の章へ

Transformer block では、LayerNorm で正規化した入力を attention と MLP に渡し、その出力を残差ストリームに足していくことを見てきました。attention は位置の間で情報を移し、MLP は各位置で `4C` 本の固定ベクトルを入力に応じた係数で足し合わせます。

すべての block を通った後のストリームは、まだ `C` 成分のベクトルです。次章では、最後の LayerNorm と `lm_head` でこれを語彙のスコアに変え、softmax で次のトークンの確率にする過程を追います。
