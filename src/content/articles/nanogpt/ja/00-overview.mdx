nanoGPT では、GPT-2 スタイルの言語モデルの学習と文章生成を行うことができます。コードは必要最小限に抑えられており、モデルの仕組みを理解しやすい構成になっています。中心となるのは、モデルを定義する約300行の `model.py` と、学習を進める約300行の `train.py` です。その補助として、データ準備、設定、生成、計測のためのコードが置かれています。

そのコンパクトな実装には、GPU、mixed precision、分散学習、checkpoint、GPT-2 weight の読み込みまで収められています。まず、**1 batch の token がどのファイルを通り、どのような多次元配列へ変わっていくのか**を追うと、計算の流れと各処理の役割をつかめます。

nanoGPT の処理は、大きく次の4つに分けられます。

1. テキストを token 列へ変えるデータ準備
2. token 列から次 token を予測する GPT 本体
3. loss から parameter を更新する学習 loop
4. 学習済み model から文章を生成する sampling

## nanoGPT が扱う範囲

nanoGPT の主題は、decoder-only Transformer による **next token 予測**です。入力された token 列から、それぞれの位置で次に来る token の score を計算します。この計算と weight 更新を大量の文章に対して繰り返せば pretraining になり、既存の weight から小さな learning rate で学習を続ければ fine-tuning になります。学習済みの weight を使って予測した token を入力へ戻し続ければ、一連の文章を生成できます。

```text
pretraining   : random weights + token data → trained weights
fine-tuning   : pretrained weights + new token data → adapted weights
generation    : trained weights + prompt → one token → append → repeat
```

ChatGPT のような対話システムを作るには、この核となるモデルに対話 format、instruction tuning、preference optimization、tool use、serving、chat UI などを組み合わせます。このシリーズでは、まず nanoGPT で言語モデルの核を学び、その後 nanochat で対話モデルの学習・評価・推論へ進みます。

### 1. データを token ID へ変える

model が受け取るのは token ID の列です。`prepare.py` で text を tokenize し、整数の並びへ変換します。

文字単位の [`data/shakespeare_char/prepare.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/data/shakespeare_char/prepare.py#L19-L61) では、登場する文字を並べて語彙を作り、`stoi` で文字から ID へ、`itos` で ID から文字へ変換します。GPT-2 と同じ BPE （Byte Pair Encoding: よく現れる並びをまとめて token にする方式）を使う dataset では、`tiktoken` が同じ役割を担います。

データ準備によって、主に次の3つのファイルが生成されます。

- `train.bin`: parameter 更新に使う token 列
- `val.bin`: 検証用の loss を見積もるために分けておく token 列
- `meta.pkl`: 文字単位 dataset の語彙サイズ と encode/decode 情報

binary file には、連結された長い token stream が入っています。学習時には、この stream の一部を切り出して context window を作ります。

### 2. 1 token ずれた input と target を作る

[`train.py` の `get_batch()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py#L114-L131) では、token 列から開始位置をランダムに $B$ 個選びます。それぞれの位置から `block_size` 個の token を入力 `x` として切り出し、開始位置を 1 token 先へずらして同じ長さを切り出したものを、正解 `y` とします。

次は、`block_size = 8` の場合の 1 サンプルです。説明のため各文字を 1 token として示していますが、実際の `x` と `y` には整数の token ID が入ります。

```text
token stream : G  P  T  は  次  を  予  測  す  る
input x      : G  P  T  は  次  を  予  測
target y     : P  T  は  次  を  予  測  す
```

batch size を $B$、入力の token 数を $T$ とすると、`x` と `y` の shape はいずれも $B \times T$ です。ここでは $T = \texttt{block\_size}$ になります。

各位置では、**その位置までの入力を使って次の token を予測**します。例えば、最初の位置では `G` から `P` を予測し、最後の位置では `GPTは次を予測` から `す` を予測します。causal mask により、各位置から未来の token への参照が制限されます。

学習時には、1 回の forward で全 $B \times T$ 位置の予測を並列に計算し、対応する `y` と比較して loss を求めます。

### 3. GPT が logits を計算する

`x` は [`GPT.forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L170-L193) へ渡されます。まず各 token ID を token embedding によって高次元のベクトルに変換し、position embedding によって token 位置も同じ次元のベクトルに変換して、両者を足し合わせます。続いて、self-attention で各位置自身とそれ以前の token の情報を取り込み、MLP で各位置の表現を更新する Transformer block を複数回通します。最後に、language-model head という線形層が各位置のベクトルを語彙数分の score に変換します。この確率に変換する前の score を **logits** と呼びます。

```python
logits, loss = model(X, Y)
```

logits の shape は $B \times T \times V$ です。$B$ は batch size、$T$ は系列長、$V$ は vocabulary size を表します。logits[b, t, v] は、batch b の位置 t までの token 列に続く次の token が v であることに対する score です。

### 4. loss から parameter を更新する

`targets` が渡された場合、`GPT.forward()` は各位置の予測確率分布と正解 token の間の cross entropy も計算します。学習 loop では、この scalar loss から gradient を求め、AdamW（gradient に基づいて更新幅を適応的に調整する最適化手法）で parameter を更新します。

```python
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()
```

実際の `train.py` では、この基本形に gradient accumulation、mixed-precision 用の `GradScaler`、gradient clipping、learning-rate schedule、DDP による gradient 同期が加わります。これらは大規模な学習を安定して効率よく実行するための処理で、後の章で詳しくみます。

### 5. checkpoint を保存し、生成に使う

一定間隔で train/validation loss を見積もり、model parameter、optimizer state、iteration、config を checkpoint へ保存します。`sample.py` はこの checkpoint を読み込み、`model.generate()` を呼びます。

生成時は、それまでの token 列をもとに続きを予測します。最後の位置の logits を temperature で調整し、必要なら top-k に候補を絞ってから softmax を適用し、次の token を1つ sample します。選んだ token を input の末尾へ追加し、同じ処理を繰り返します。

## `model.py` の内部構造

[`model.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py) では、下位の module から順に `LayerNorm`、`CausalSelfAttention`、`MLP`、`Block`、`GPT` が定義されています。実行時の包含関係は次のようになります。

```text
GPT
├── token embedding (wte)         [V, C]
├── position embedding (wpe)      [T, C]
├── Block × n_layer
│   ├── LayerNorm
│   ├── CausalSelfAttention
│   │   ├── c_attn                C → 3C (Q, K, V)
│   │   └── c_proj                C → C
│   ├── LayerNorm
│   └── MLP                       C → 4C → C
├── final LayerNorm
└── language-model head           C → V
```

ここで $C$ は embedding dimension（`n_embd`）、$H$ は attention head の数（`n_head`）です。各 head の次元数は $d_{\text{head}} = C/H$ で、$C$ は $H$ で割り切れる必要があります。model 内の中心的な shape は、次のように変化していきます。

| 段階                | shape                            | 値の意味                       |
| ------------------- | -------------------------------- | ------------------------------ |
| token ID            | $B \times T$                     | 語彙表への index               |
| token embedding     | $B \times T \times C$            | token ごとの学習可能な vector  |
| position embedding  | $T \times C$                     | sequence 内の位置を表す vector |
| query / key / value | $B \times H \times T \times C/H$ | attention head ごとの表現      |
| attention weight    | $B \times H \times T \times T$   | 各位置から過去の各位置への重み |
| residual stream     | $B \times T \times C$            | block 間を流れる hidden state  |
| logits              | $B \times T \times V$            | 次 token 候補の score          |

### causal self-attention

[`CausalSelfAttention`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L29-L76) が受け取る入力は、各 token 位置に $C$ 次元のベクトルを持つ、shape が $B \times T \times C$ の多次元配列です。最初の Transformer block では token embedding と position embedding を足し合わせた表現を、2 層目以降では前の block の出力を使います。各 block では、その表現に LayerNorm で各 token 位置のベクトルの平均と分散を整えてから `CausalSelfAttention` へ渡します。

Attention は、各 token 位置について、それ以前のどの位置の情報をどれだけ取り込むかを決め、重みに従って情報を集める処理です。**Multi-head attention では、この処理を複数並列に行い、その一つひとつを head と呼びます**。各 head では、どの位置を重視するかの判断基準と、そこから取り込む情報の表現をそれぞれ学習するため、同じ入力から異なる関係や特徴を捉えることができます。

各 head では、入力の $C$ 次元ベクトルから、それぞれ $d_{\text{head}}=C/H$ 次元の query、key、value ベクトルを作ります。query と key は位置どうしの参照の重みを決めるための表現で、value はその重みに従って集める情報を表します。実装上は、$H$ 個の head の query、key、value の線形変換をまとめて行います。具体的には、各 token の $C$ 次元ベクトルを $3C$ 次元に変換し、 query、key、value に対応する $C$ 次元ずつに分け、さらに $H$ 個の head に分割します。最終的な shape は $B \times H \times T \times d_{\text{head}}$ です。

1 サンプルの 1 head に注目すると、query、key、value はそれぞれ $T \times d_{\text{head}}$ の 2 次元配列 $Q$、$K$、$V$ になります。参照の重み $A$ と出力 $Y$ は、次のように計算します。

$$
A = \operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_{\text{head}}}} + M\right),
\qquad Y = AV
$$

ここで、$M$ は causal mask で、未来位置の score を $-\infty$ にすることで、softmax 後の重みを0にする働きがあります。これにより、位置 $t$ での予測が参照する範囲を、位置 $0$ から $t$ までに限定します。

PyTorch が対応していれば、nanoGPT は `scaled_dot_product_attention` の fused 実装を使います。対応していない環境では、mask、softmax、value との積をコード上で明示的に計算します。計算の意味は同じですが、後者の方が中間の多次元配列を観察しやすくなります。

### MLP と residual stream

attention が token 位置どうしの情報を混ぜるのに対し、[`MLP`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L78-L92) は各 token 位置のベクトルを個別に変換します。具体的には、$C$ 次元のベクトルを線形変換で $4C$ 次元に広げ、非線形な活性化関数 GELU を通した後、別の線形変換で $C$ 次元に戻します。これにより、各位置のベクトルの成分（channel）を組み合わせて、より複雑な特徴を表現できます。MLP はすべての位置に同じ変換を適用し、位置どうしの情報は混ぜません。

[`Block`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L94-L106) では、LayerNorm を通した入力を attention と MLP で順に処理し、それぞれの出力を入力に足し合わせます。この仕組みを residual connection（残差接続） と呼び、各処理を通さずに元の情報を直接引き継ぐ経路を作ることで、深いネットワークでも学習を進めやすくします。

Attention も MLP も出力は $C$ 次元なので、足し合わせた後も x の shape は $B \times T \times C$ のままです。このように各 block を通じて更新されていく x を residual stream と呼びます。このシリーズでは、同じ shape を保ちながら、その中の値が各層でどのように変化していくのかを追っていきます。

### 最後に logits へ戻す

すべての Transformer block を通った後、各 token 位置の $C$ 次元ベクトル（hidden state）に最後の LayerNorm を適用します。続いて `lm_head` が、語彙に含まれる $V$ 種類の token それぞれについて、次の token としてのスコアを計算します。この $V$ 次元のスコアを logits と呼び、softmax を適用することで各 token が次に現れる確率に変換できます。

`lm_head` と token embedding は同じ weight を共有します。入力時には token ID から $C$ 次元ベクトルを取り出すために使った表を、出力時には hidden state と各 token のベクトルの内積からスコアを計算するために再利用します。

学習時にはすべての位置について logits を計算するため、出力の shape は $B \times T \times V$ になります。一方、文章の生成時には、最後の位置の logits を使って次の token を選びます。

## `train.py` を役割ごとに読む

[`train.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py) は長く見えますが、上から6つの区画に分けると整理しやすくなります。

1. **default config** — dataset、model size、optimizer、評価間隔、device などを定義する。
2. **runtime setup** — 単一 process か DDP かを判定し、seed、device、dtype、autocast を準備する。
3. **data loading** — `np.memmap` で binary を開き、`get_batch()` で `X, Y` を作る。
4. **model setup** — scratch、checkpoint 再開、pretrained GPT-2 のいずれかから model を作り、optimizer を設定する。
5. **evaluation and scheduling** — train/validation loss と learning rate を計算し、checkpoint 条件を判断する。
6. **training loop** — forward、backward、gradient 処理、optimizer step、logging を繰り返す。

model の初期化には3つの入口があります。

| `init_from` | 開始状態                                 | 用途                            |
| ----------- | ---------------------------------------- | ------------------------------- |
| `scratch`   | random に初期化した weight               | pretraining を最初から行う      |
| `resume`    | `out_dir/ckpt.pt` の model と optimizer  | 中断した学習を続ける            |
| `gpt2*`     | Hugging Face から読み込んだ GPT-2 weight | 評価または fine-tuning を始める |

この3つの経路は開始時の weight こそ異なりますが、最終的には同じ `GPT` instance と同じ training loop へ合流します。

## 学習と生成はどこまで同じか

学習と生成は、token ID から hidden state と logits を得るところまで同じ model を共有します。違うのは、得られた logits をどのように使うかです。

|                 | 学習                    | 生成                                   |
| --------------- | ----------------------- | -------------------------------------- |
| model への入力  | token ID `X` と正解 `Y` | prompt と、それまでに生成した token ID |
| 必要な logits   | 全 $B \times T$ 位置    | 最後の1位置                            |
| logits の使い方 | cross entropy を計算    | softmax して次 token を選ぶ            |
| parameter       | gradient で更新する     | 固定する                               |
| 繰り返し単位    | batch                   | 生成する1 token                        |

`train.py` と `sample.py` は、同じ `GPT.forward()` をそれぞれ学習と生成のために呼び出しています。

## config は実験条件そのもの

nanoGPT では、architecture と学習条件を `train.py` の default から、`config/*.py` と `--key=value` で上書きします。[`configurator.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/configurator.py#L20-L47) は小さな仕組みですが、実験の再現性を考える上では重要です。

### デフォルトのモデル構成とパラメータ数

参照元リポジトリには、OpenWebText 用のデフォルト、Shakespeare の文字単位（char）用設定、GPT-2 の BPE を使う Shakespeare 用設定があります。以下は、それぞれを追加の上書きなしで使った場合のモデル構成です。

- **OpenWebText**：[`train.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py) のデフォルトで、GPT-2 相当のモデルを新規学習します。
- **Shakespeare char**：[`config/train_shakespeare_char.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/config/train_shakespeare_char.py) で、小型モデルを新規学習します。
- **Shakespeare BPE**：[`config/finetune_shakespeare.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/config/finetune_shakespeare.py) で、学習済みの **GPT-2 XL** を読み込み、fine-tuning します。

<summary>表の注</summary>

attention の内訳は、query・key・value を作る線形変換（$3C^2$）と出力の線形変換（$C^2$）、および有効な場合の bias です。MLP は拡張・縮小の 2 つの線形変換（それぞれ $4C^2$）と bias、LayerNorm は各 block の 2 か所と最終層の scale・bias を数えます。$C$ を固定すると、head 数 $H$ は各 head の次元数を変え、attention の総パラメータ数は同じになります。入力ごとに計算される参照の重み $A$（attention weight）は中間計算の値なので、この集計から除きます。

BPE 用設定の 48 blocks・25 heads・1,600 次元は、`init_from='gpt2-xl'` によって [`GPT.from_pretrained()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L207-L234) が選ぶ構成です。データの token 化とモデルの規模は別々に設定できます。この表の規模の違いは、参照元リポジトリが用意した新規学習・fine-tuning の設定に由来します。

OpenWebText の 50,304 は、GPT-2 の語彙数 50,257 を計算効率のために 64 の倍数へ切り上げた値です。Shakespeare char の 65 は、[データ準備時に数えた文字の種類数](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/data/shakespeare_char/prepare.py) を `meta.pkl` から読み込みます。学習済み GPT-2 XL は元の語彙サイズ 50,257 を使います。

総パラメータ数は、[`model.py` の `GPT`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L118-L169) に上表の構成を渡し、`sum(p.numel() for p in model.parameters())` で数えた値です。学習可能な重みの各要素を数え、bias と LayerNorm の学習可能な値、token embedding、position embedding を含めています。token embedding と出力層は重みを共有するため、共有分は 1 回だけ数えます。nanoGPT が起動時に表示する `get_num_params()` の値は position embedding を除くため、この表の総数より小さくなります。

model size、batch size、learning rate、iteration 数、dropout、評価回数、device は、いずれも結果や実行時間に影響します。実験を再現できるように、使用した config と commit を記録します。

**Linear 層・LayerNorm の `bias`** は、学習可能な加算項を使うかどうかを指定します。Linear 層では線形変換の結果に bias を足し、LayerNorm では正規化した値に学習可能な scale を掛けた後、bias を足します。`False` の場合も Linear 層の weight と LayerNorm の scale は学習します。`lm_head` はこの設定によらず `bias=False` です。

**`dropout`** は、学習時に dropout を適用する箇所で、各要素をランダムに 0 にする確率です。たとえば `0.2` は各要素を 20% の確率で 0 にし、残した値を $1/(1-0.2)$ 倍にします。nanoGPT では embedding の加算結果、attention の参照の重みと出力、MLP の出力に適用し、特定の特徴への依存を抑えます。評価・文章生成時には無効になります。dropout 自体には学習可能なパラメータはありません。

</details>

## このシリーズでの学び方

この先では、同じ end-to-end flow を4段階に分けて深掘りしていきます。

### Phase 1 — data を作る

第1–2章では、text を token ID へ変換し、長い token stream から context window と正解を作ります。ここで見る中心的な値は、`stoi` / `itos`、token 列、`X [B,T]`、`Y [B,T]` です。

### Phase 2 — forward pass を分解する

第3–8章では、`GPT.forward()` を embedding、position、self-attention、multi-head attention、MLP、residual stream、logits、loss へと分けて見ていきます。各段階で 多次元配列の shape、値の範囲、各軸の意味を可視化します。

### Phase 3 — model が学ぶ仕組みを見る

第9–11章では、loss から gradient がどのように伝わるのか、optimizer がどの parameter をどう更新するのか、train/validation loss をどう読むのかを扱います。最後に小規模な GPT を実際に学習させ、学習前後の出力を比較します。

### Phase 4 — 規模と system の違いへ進む

第12章では、parameter 数、context length、batch size、compute の trade-off を実験します。第13章では、nanoGPT で扱った pretraining の核を出発点に、nanochat が追加する data、evaluation、inference、chat 向けの処理へ進みます。
