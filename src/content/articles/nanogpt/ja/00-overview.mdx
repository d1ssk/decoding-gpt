## nanoGPT が扱う範囲

nanoGPT は、GPT-2 と同じ構成の言語モデルを学習し、文章を生成するためのコードです。中心は、モデルを定義する約 300 行の `model.py` と、学習を進める約 300 行の `train.py` で、そのまわりにデータ準備、設定、生成、速度計測のためのコードがあります。GPU での実行、混合精度、分散学習、checkpoint、学習済み GPT-2 の重みの読み込みも、この小さなコードに含まれています。

nanoGPT の主題は、decoder-only Transformer による **次のトークンの予測**です。モデルはトークンの列を受け取り、各位置で、次に来るトークンの候補それぞれにスコアを付けます。この計算と重みの更新を大量の文章で繰り返すと事前学習（pretraining）、既存の重みから小さな学習率で学習を続けると fine-tuning、予測したトークンを入力の末尾に戻し続けると文章の生成になります。

```text
pretraining   : random weights + token data → trained weights
fine-tuning   : pretrained weights + new token data → adapted weights
generation    : trained weights + prompt → one token → append → repeat
```

ChatGPT のような対話システムは、このモデルに、会話の形式、指示に従うための追加学習、好ましい応答を選ぶ学習、ツールの利用、推論サーバー、チャット画面などを組み合わせて作ります。このシリーズでは、まず nanoGPT で言語モデルの核を読み、最後の第 13 章で nanochat の対話モデルへ進みます。

次の図は、このシリーズの第 11 章で実際に学習する小さなモデル（約 80 万パラメータ）が生成した文章です。第 1 章から第 10 章では、学習前のランダムな文字列が更新 2,000 回後の文章に変わるまでに、どのような計算が行われているかを順に読みます。

### 1. テキストを token ID に変える

モデルが受け取るのは token ID の列です。文字単位の [`data/shakespeare_char/prepare.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/data/shakespeare_char/prepare.py#L19-L61) は、本文に現れる文字を並べて語彙を作り、`stoi` で文字から ID へ、`itos` で ID から文字へ変換します。GPT-2 の BPE を使うデータセットでは、`tiktoken` が同じ役割を担います。

準備の結果、学習に使う `train.bin`、検証に使う `val.bin`、文字単位の語彙を保存した `meta.pkl` ができます。`.bin` ファイルには、本文全体をつなげた 1 本の長いトークン列が入っています。詳しくは[第 1 章](../01-text-to-tokens/)で扱います。

### 2. 1 トークンずらした入力と正解を作る

[`train.py` の `get_batch()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py#L116-L131) は、トークン列から `B` 個の開始位置をランダムに選び、それぞれから `block_size` 個のトークンを入力 `X` として切り出します。開始位置を 1 トークン先にずらして切り出したものが、正解 `Y` です。

```text
トークン列 : G  P  T  は  次  を  予  測  す  る
入力 X     : G  P  T  は  次  を  予  測
正解 Y     : P  T  は  次  を  予  測  す
```

説明のため各文字を 1 トークンとしていますが、実際の `X` と `Y` には整数の token ID が入ります。どちらも形状 `[B, T]` の 2 次元配列で、`T = block_size` です。各位置では、その位置までの入力から次のトークンを予測します。1 回の forward で全 `B × T` 位置の予測をまとめて計算できるのは、causal mask が未来の位置の参照を防ぐためです。詳しくは[第 2 章](../02-context-and-training-examples/)で扱います。

### 3. GPT が logits を計算する

```python
logits, loss = model(X, Y)
```

[`GPT.forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L170-L193) は、token ID を埋め込みベクトルに変え、Transformer block を繰り返し通し、最後に語彙の各トークンのスコア **logits** を計算します。logits の形状は `[B, T, V]` で、`V` は語彙サイズです。`logits[b, t, v]` は、サンプル `b` の位置 `t` までの入力に続くトークンが `v` であることへのスコアです。

### 4. 損失から重みを更新する

`targets` を渡すと、`GPT.forward()` は各位置の予測と正解の cross entropy も計算します。学習ループは、このスカラーの損失から勾配を求め、AdamW で重みを更新します。

```python
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()
```

実際の `train.py` では、この基本形に、勾配の蓄積、混合精度用の `GradScaler`、勾配のクリップ、学習率のスケジュール、DDP による勾配の同期が加わります。損失は[第 8 章](../08-loss/)、勾配は[第 9 章](../09-backpropagation/)、更新の手順は[第 10 章](../10-training-loop/)で扱います。

### 5. checkpoint を保存し、生成に使う

学習中は一定間隔で学習用・検証用の損失を見積もり、重み、optimizer の状態、更新回数、設定を checkpoint に保存します。`sample.py` は checkpoint を読み込んで `model.generate()` を呼び、最後の位置の logits から次のトークンを 1 つ選んで入力の末尾に追加する処理を繰り返します。生成の手順は[第 7 章](../07-hidden-states-to-probabilities/)、実際の学習と生成は[第 11 章](../11-train-a-tiny-gpt/)で扱います。

## `model.py` の内部構造

[`model.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py) では、`LayerNorm`、`CausalSelfAttention`、`MLP`、`Block`、`GPT` が、小さなモジュールから順に定義されています。実行時の包含関係は次のとおりです。

```text
GPT
├── token embedding (wte)         [V, C]
├── position embedding (wpe)      [block_size, C]
├── Block × n_layer
│   ├── LayerNorm (ln_1)
│   ├── CausalSelfAttention
│   │   ├── c_attn                C → 3C (Q, K, V)
│   │   └── c_proj                C → C
│   ├── LayerNorm (ln_2)
│   └── MLP                       C → 4C → C
├── final LayerNorm (ln_f)
└── lm_head                       C → V
```

`C` は埋め込みの次元数（`n_embd`）、`H` は attention head の数（`n_head`）、`d = C / H` は head ごとの成分数です。モデルの中で、主な配列の形状は次のように変わります。

| 段階                | 形状           | 値の意味                                 | 章                                               |
| ------------------- | -------------- | ---------------------------------------- | ------------------------------------------------ |
| token ID `idx`      | `[B, T]`       | 語彙の項目を指定する番号                 | [第 1〜2 章](../01-text-to-tokens/)              |
| 埋め込みの和        | `[B, T, C]`    | 各位置のトークンと位置を表すベクトル     | [第 3 章](../03-embeddings-and-position/)        |
| query / key / value | `[B, H, T, d]` | head ごとの参照用・集約用のベクトル      | [第 4〜5 章](../04-self-attention/)              |
| 参照の重み `att`    | `[B, H, T, T]` | 各位置から自分自身と過去の各位置への重み | [第 4〜5 章](../04-self-attention/)              |
| 残差ストリーム `x`  | `[B, T, C]`    | block の間を流れる各位置のベクトル       | [第 6 章](../06-mlp-and-residual-stream/)        |
| logits              | `[B, T, V]`    | 次のトークンの候補ごとのスコア           | [第 7 章](../07-hidden-states-to-probabilities/) |
| 損失 `loss`         | `[]`           | 全位置の cross entropy の平均            | [第 8 章](../08-loss/)                           |

各 block では、LayerNorm で正規化したベクトルを attention と MLP に順に渡し、それぞれの出力を残差ストリームに足します。attention は位置の間で情報を集め、MLP は各位置のベクトルを個別に変換します。足し算の後も形状は `[B, T, C]` のままなので、block を何層重ねても形状は変わりません。最後の LayerNorm の後、`lm_head` が各位置のベクトルを語彙サイズ `V` 個のスコアに変えます。`lm_head` の重みは、入力側のトークン埋め込みと共有されています。

attention には、計算を 1 つの関数にまとめた `scaled_dot_product_attention` を使う経路と、mask、softmax、value との積を順に計算する経路があります。このシリーズでは、中間の配列を観察できる後者の経路を読みます。

## `train.py` を役割ごとに読む

[`train.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py) は、上から 6 つの区画に分けると整理しやすくなります。

1. **既定の設定**：データセット、モデルの大きさ、optimizer、評価の間隔、実行するデバイスなどを定義する。
2. **実行環境の準備**：単一プロセスか DDP かを判定し、乱数 seed、デバイス、データ型、autocast を準備する。
3. **データの読み込み**：`np.memmap` でバイナリファイルを開き、`get_batch()` で `X, Y` を作る。
4. **モデルの準備**：新規作成、checkpoint からの再開、学習済み GPT-2 の読み込みのいずれかでモデルを作り、optimizer を設定する。
5. **評価とスケジュール**：学習用・検証用の損失と学習率を計算し、checkpoint を保存するかを判断する。
6. **学習ループ**：forward、backward、勾配の処理、optimizer の更新、ログ出力を繰り返す。

モデルの初期化には 3 つの入口があります。

| `init_from` | 開始時の状態                             | 用途                          |
| ----------- | ---------------------------------------- | ----------------------------- |
| `scratch`   | ランダムに初期化した重み                 | 事前学習を最初から行う        |
| `resume`    | `out_dir/ckpt.pt` のモデルと optimizer   | 中断した学習を続ける          |
| `gpt2*`     | Hugging Face から読み込んだ GPT-2 の重み | 評価または fine-tuning を行う |

どの入口でも、最終的には同じ `GPT` のインスタンスと同じ学習ループに合流します。

## 学習と生成はどこまで同じか

学習と生成は、token ID から logits を計算するところまで同じモデルを使います。違うのは logits の使い方です。

|                 | 学習                    | 生成                                      |
| --------------- | ----------------------- | ----------------------------------------- |
| モデルへの入力  | token ID `X` と正解 `Y` | プロンプトと、それまでに生成した token ID |
| 使う logits     | 全 `B × T` 位置         | 最後の 1 位置                             |
| logits の使い方 | cross entropy を計算    | softmax で確率にし、次のトークンを選ぶ    |
| 重み            | 勾配で更新する          | 固定する                                  |
| 繰り返しの単位  | バッチ                  | 生成する 1 トークン                       |

`train.py` と `sample.py` は、同じ `GPT.forward()` をそれぞれ学習と生成のために呼び出しています。

## 設定とモデルの規模

nanoGPT では、モデルの構成と学習の条件を、`train.py` の既定値から `config/*.py` と `--key=value` で上書きします。[`configurator.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/configurator.py#L20-L47) は小さな仕組みですが、実験を再現するうえで重要です。

### 設定ごとのモデル構成とパラメータ数

次の表は、参照元リポジトリが用意した 3 つの設定と、このシリーズの第 11 章で実際に学習する設定のモデル構成です。

- **OpenWebText**：[`train.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py) の既定値で、GPT-2 相当のモデルを新規に学習します。
- **Shakespeare char**：[`config/train_shakespeare_char.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/config/train_shakespeare_char.py) で、文字単位の小型モデルを新規に学習します。
- **Shakespeare BPE**：[`config/finetune_shakespeare.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/config/finetune_shakespeare.py) で、学習済みの **GPT-2 XL** を読み込み、fine-tuning します。

| 総数の概数（M = 100 万）         | —                     |         124.37M |           10.75M |         1,557.61M |       0.80M |

</div>

<details className="model-parameters-notes">
<summary>表の注</summary>

attention の内訳は、query・key・value を作る線形変換（$3C^2$）と出力の線形変換（$C^2$）、および有効な場合の bias です。MLP は拡張・縮小の 2 つの線形変換（それぞれ $4C^2$）と bias、LayerNorm は各 block の 2 か所と最終層の scale・bias を数えます。$C$ を固定すると、head 数 $H$ は各 head の成分数を変え、attention の総パラメータ数は同じになります。入力ごとに計算される参照の重み `att` は中間の値なので、この集計から除きます。

BPE 用設定の 48 blocks・25 heads・1,600 次元は、`init_from='gpt2-xl'` によって [`GPT.from_pretrained()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L207-L234) が選ぶ構成です。データのトークン化とモデルの規模は別々に設定できます。

OpenWebText の 50,304 は、GPT-2 の語彙数 50,257 を計算効率のために 64 の倍数へ切り上げた値です。文字単位の 65 は、[データ準備時に数えた文字の種類数](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/data/shakespeare_char/prepare.py) を `meta.pkl` から読み込みます。学習済み GPT-2 XL は元の語彙サイズ 50,257 を使います。

総パラメータ数は、[`model.py` の `GPT`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L118-L169) に上表の構成を渡し、`sum(p.numel() for p in model.parameters())` で数えた値です。トークン埋め込みと出力層は重みを共有するため、共有分は 1 回だけ数えます。nanoGPT が起動時に表示する `get_num_params()` の値は位置埋め込みを除くため、この表の総数より小さくなります。第 11 章の設定では、表示は `0.80M`（795,904）です。

モデルの大きさ、バッチサイズ、学習率、更新回数、dropout、評価の回数、デバイスは、いずれも結果や実行時間に影響します。実験を再現できるように、使用した設定と commit を記録します。

**Linear 層・LayerNorm の `bias`** は、学習可能な加算項を使うかどうかを指定します。`False` の場合も Linear 層の重みと LayerNorm の scale は学習します。`lm_head` はこの設定によらず `bias=False` です。

**`dropout`** は、学習時に各要素をランダムに 0 にする確率です。nanoGPT では埋め込みの和、attention の参照の重みと出力、MLP の出力に適用します。評価・生成時には無効になります。詳しくは[第 3 章](../03-embeddings-and-position/)で扱います。

## ソースコードを読む順序

最初は、次の順番でデータの値と計算を追うと、処理全体のつながりをつかみやすくなります。

1. [`data/shakespeare_char/prepare.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/data/shakespeare_char/prepare.py) で、テキストと token ID の対応を見る（第 1 章）。
2. [`train.py` の `get_batch()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py#L116-L131) で、`X` と `Y` が 1 トークンずれていることを確かめる（第 2 章）。
3. [`GPT.forward()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L170-L193) を、埋め込みから logits まで一度通して読む（第 3 章・第 7 章）。
4. [`Block`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L94-L106) と [`CausalSelfAttention`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L29-L76) に降り、途中の配列の形状を追う（第 4〜6 章）。
5. [`train.py` の学習ループ](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/train.py#L249-L333) に戻り、損失から更新までを見る（第 8〜10 章）。
6. [`GPT.generate()`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py#L305-L330) と [`sample.py`](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/sample.py) で、出力したトークンが次の入力になるループを見る（第 7 章・第 11 章）。

## このシリーズの進め方

この先の章では、同じ流れを 4 つの段階に分けて読みます。

### 段階 1：データを作る

第 1〜2 章では、テキストを token ID に変換し、長いトークン列から入力と正解のバッチを作ります。中心となる値は、`stoi` / `itos`、トークン列、`X [B, T]`、`Y [B, T]` です。

### 段階 2：forward を分解する

第 3〜8 章では、`GPT.forward()` を、埋め込み、self-attention、multi-head attention、MLP と残差ストリーム、logits、損失に分けて読みます。各段階で、配列の形状、値の範囲、各軸の意味を可視化します。

### 段階 3：モデルが学ぶ仕組みを見る

第 9〜11 章では、損失から勾配がどのように伝わるか、optimizer が重みをどう更新するかを読み、実際に小さな GPT を学習させて、学習の前後で出力を比べます。

### 段階 4：規模と、より大きなシステムへ

第 12 章では、モデルの大きさ、学習の長さ、文脈の長さを変えて学習し、損失との関係を確かめます。第 13 章では、nanoGPT で読んだ事前学習の核を出発点に、nanochat が加えるデータ、評価、推論、対話向けの処理へ進みます。
